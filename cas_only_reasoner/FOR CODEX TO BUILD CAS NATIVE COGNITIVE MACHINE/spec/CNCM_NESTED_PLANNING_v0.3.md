# CNCM native nested dependency planning v0.3

Status: VERSIONED CONTRACT. Current implementation and acceptance evidence are
retained separately in records/nested_planning_001/STATUS.md. This opt-in runtime
extends native equation planning and shared procedural memory. It does not close the complete charter,
demonstrate new arithmetic program synthesis, or claim a learned planning policy.
All runtime0.1 and native0.2 source and authority artifacts remain unchanged.

## Source, problem and discovery

The authority source remains cas_reasoner.txt, SHA-256
a72312231bfb346dc4895b1a0963e0c255d26b707c8a4fbc94d90ac52979dfea.
Phase3 requires memory-bound derivation, actual prerequisite discovery, exact
nested returns, invalid-proof rejection and bounded cycle-checked RPM.

A problem supplies at most16 uniquely named equations and a query variable.
Each equation is a*v+b = constant + sum(coefficient*dependency), with at most4
distinct nonzero dependency terms. Rationals and variable identities are strict
canonical data. The problem supplies neither answers nor an execution order,
resolver, completed graph or expected program. Missing variable producers and
cycles remain live planning failures, rather than fabricated values.

Decomposition derives dependencies from the original equation. The coordinator
opens missing children in canonical variable order and records every step.
Already COMPLETE prerequisites are reused only through their exact checked
execution records. Unreachable equations are not executed. Multiple parents
may reuse one checked dependency in the same run. Each requested variable has
one deterministic call identity bound to the current run and equation.

## State, writer and authority

Runtime0.3.0 uses its own strict state, proof, frame, problem and source profile.
The existing TransactionCoordinator remains the sole writer through an explicit
new subclass. ProcedureArtifact, the six-instruction executor and independent
CAS-Math checker are reused unchanged. Installation still requires the public
engineering panel; this is not neural learning or secret empirical qualification.

Each call has its own immutable dependency workspace, inputs and result.
Child results do not write the root branch. While a parent is suspended, its
call content and the entire parent reasoning branch are pinned by the frame.
Returning one child may bind only that exact completed execution or propagate
its recorded failure. The saved call, goal, return address, resume stage, branch,
depth and entry budget must reconstruct. A numeric answer with a familiar name
is not a dependency proof.

A procedure acquisition may nest inside dependency planning. All frames share
one instruction/checker budget and one active registry. No child boot or
return resets a budget. At most8 frames may be active, further limited by the
problem's RPM depth allowance. Cycle/depth/missing-input failures unwind to the
original caller with evidence. Tick exhaustion may retain unresolved frames;
such a terminal state cannot start a new budget episode.

## Grounding, execution and proof

All equation coefficients/constants and admitted procedure inputs are bounded
to128-bit canonical rationals. Child outputs may be512-bit exact rationals
under the frozen executor. An output outside the next input's128-bit bound is
a typed composition failure; the coordinator must not silently widen that
contract or approximate the value.

The0.3 canonical wire admits bounded512-bit integer payloads because exact
CAS-Math receipts contain integer numerators and denominators. Typed budgets,
ticks, lengths and all other counter fields retain their narrower bounds.

The grounding stage computes only the right-hand expression from exactly cited
checked dependencies, using bounded rational arithmetic. It never solves for
the requested variable. The installed artifact remains the sole producer of
the candidate answer. The existing exact substitution checker checks that
answer against grounded a*x+b=c. A separate equation checker then substitutes
it into the original equation and recomputes the referenced right side.
Neither receipt alone grants state or commitment authority.

Only a COMPLETE queried call with its complete checked dependency closure and
an empty RPM stack adds a nested_checked(query_variable) root proof to the
reasoning branch. Ordinary decomposition, inference, comparison, selection,
contradiction and commitment gates still apply. Other input propositions cannot
assert or derive this reserved checked predicate. The viewer has no authority.

## Conservative work and refusal

Each selection reserves144 instructions and24 checker calls; installation
reserves60/10. Grounding reserves12/0; application reserves18/2, including the
frozen executor's6/1 and the original-equation check's12/1. These are abstract
bounded policy units, not measured CPU operations, time, energy or money.
Parsing and the finite16-node dependency walk are bounded validation.

Cheap authority/type/scope/current-state/frame/identity checks precede work.
The whole allocation is debited before checking. Refused checked attempts keep
their debit and full trace; repeated checks cannot become free work.
No allocation refund is implemented. Qualification and selection records retain
their actual execution counters separately from conservative reservations.

A refused proposal does not erase an already checked child. Its canonical
return may still be attempted afterward. Unfinished calls with rejected work
instead record the refusal and unwind; a malformed return never binds a value.

New native transactions contain one intent. Duplicate/malformed proposal
occurrences are preserved for replay; legacy grouping cannot erase them.
The closed issuer/intent/capability matrix is in the separate0.3 manifest.
No intent grants file/network access, external action, constitutional edits,
checker changes, or authority from a teacher label.

## Recovery, reuse and rollback

Journals retain trusted-genesis binding, all episode problems, original proposal
occurrences, full transitions and final states. A fresh process replays every
transition through the same coordinator and source profile. It compares the
entire reconstructed trace and state. Saved state, successful labels, and
rehashed false histories are never imported as authority.

A new episode can inherit the registry only from the host's preceding terminal
coordinator state with no unresolved frame. Prior records stay immutable.
First-installation rollback is permitted only before this episode opens any
call. Future calls must then reacquire or report unavailable capability.
Active version replacement remains outside this contract.

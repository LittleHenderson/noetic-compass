## Original problem and construction grammar

The problem supplies a*(b*x+c)+d=e through five typed scalar parameters and the
query variable. Scalars are canonical128-bit rational literals or exact scoped
memory references. No execution graph, intermediate answer, resolver, candidate
program or finished solution is supplied. Source statements/updates use the0.4
provenance rules: USER_ATTESTED and TEST_FIXTURE never become verified world
facts. An independent checker reconstructs every scalar from admitted sources.

CallProgram pins the exact existing linear-procedure artifact. Each call binds
that primitive's a,b,c ports to parameter references or a previous call's output.
Its executable body contains one or two calls and returns the last call output.
Literal answers, general Python execution, branches, loops and arbitrary I/O are
not in this grammar. The primitive executor alone produces candidate numbers.

Construction enumerates60 one-call programs: ordered selections of three distinct
input names. It also enumerates360 two-call programs: the first uses three distinct
inputs; the second uses the two remaining inputs and r0 in every ordering. Four
fixed development cases test all420 candidates. A complete search must leave one
survivor. A bounded prefix under420 reports SEARCH_EXHAUSTED even if its prefix
already contains a passing candidate. This is deterministic finite construction,
not a learned search policy or an authored ready two-call template.

The resulting structure is sealed and independently qualified on eight disjoint
positive examples plus four invalid-domain cases. These are public engineering
panels, not secret or externally protected examinations. Every actual invocation
is still checked against the original expression after its program executes.
The checker substitutes x and compares a*(b*x+c)+d with e; it does not solve for x.
Both leading factors must be nonzero. Rational arithmetic has explicit input and
intermediate limits; a512-bit output cannot silently enter a128-bit call input.

## Native acquisition and exact continuation

The transaction coordinator is the sole state writer. An absent compound skill
suspends a real caller under ACQUIRE_COMPOUND. If its primitive is absent, that
child itself suspends under ACQUIRE_PRIMITIVE. Primitive finite selection and
qualification/install occur first. The inner frame returns to construction;
construction, separate qualification/install, and the outer return then restore
the original caller. Calls, goals, return addresses, resume stages, saved parent
digests, branch contents and entry budgets must reconstruct at every return.

The same instruction/checker budget funds memory, primitive acquisition,
construction, qualification and the final call. No child boot or return refreshes
it. Policy reservations are primitive selection144/24, primitive installation60/10,
construction96/4 per attempted grammar candidate (maximum40320/1680), compound
installation288/12 and application24/1. Memory retains its governed allocations.
Failed expensive checks keep their allocations; there is no refund. Units are
conservative design budgets, not CPU measurements, physical energy or money.

Only a checked completed call, empty RPM stack, exact input/source resolution,
current program authorization and active pinned primitive can support the reserved
root proof. Ordinary decomposition, inference, comparison and commitment still
control the final conclusion. A program or checker receipt has no direct write
or commitment authority. Native0.3 transition envelopes cannot enter this version.

## Persistence, dependency authorization and rollback

Programs, primitive artifacts, source claims and all accepted/failed work records
are retained across authorized terminal/quiescent episode boundaries. New task
bindings are recomputed. A later source correction can arrive at such a boundary
through explicit trusted-host ingress extension. Recovery requires the initial
source set and exact externally retained extension chronology. A journal cannot
authorize its own facts or import a successful state snapshot.

Every compound dispatch requires its pinned primitive bytes to be the currently
authorized primitive head. Compound rollback removes compound dispatch while
retaining its artifact/history and the primitive. Primitive rollback removes
primitive dispatch and thereby prevents dependent compound execution, even while
the old compound artifact/head remains inspectable. Reacquiring the identical
primitive may restore its dependent program; each new call is independently checked.
Rollback requires checked memory resolution and no opened call/active frame in
the new episode. Runtime policy remains host/genesis/source-bound, not principal
authentication, autonomous constitutional editing or a general package trust chain.

Journals preserve every proposed occurrence, rejection, accepted mutation, budget,
input/source binding, frame and outcome. A separate process must replay and resume
each pause point to identical complete histories. Unresolved frames prohibit a
new-budget episode. Missing capability, domain, bounded-search, depth, budget and
checker failures produce explicit refusals and checked stack unwinding.

# CNCM derived-result memory v0.6 — integration contract

Status: versioned integration contract. Runtime acceptance requires separate
execution receipts; this specification grants no completeness claim.

## Purpose and charter fit

Connect governed memory, recursive prerequisite handling and independent formal
verification in one executing machine. This extends runtime0.5 without editing
its frozen sources. The relevant charter is `cas_reasoner.txt` lines12899–13070;
its SHA-256 is
`a72312231bfb346dc4895b1a0963e0c255d26b707c8a4fbc94d90ac52979dfea`.

The required change is observable in a later derivation: an admitted checked
result supplies a missing input without repeating candidate generation. A changed
premise must stop that reuse until a new result is checked and admitted.
This is one contribution to V05/V06/V08/V10/V16 and systems9/10/14/19/31.
The complete V01–V18,31-system,20-step charter remains open.

## Evidence types and authority

Source assertions remain `USER_ATTESTED` or `TEST_FIXTURE`. A separate derived
reference requests `CHECKED_FORMAL_DERIVATION`. An accepted derivation establishes
an exact mathematical consequence conditional on its admitted original equation
and premises. It does not establish world truth, independent source authorship,
a probability, general learning or neural improvement.

A typed record, hash, saved checker label or successful deserialization grants no
write authority. Only a versioned transaction coordinator may admit a result,
bind it into a caller, update use metadata or advance the real continuation.
Actual mathematical candidates remain proposals until the protected math checker
reconstructs their relation to the pinned original equation.

The host supplies external source and definition authority at genesis and explicit
quiescent extensions. Journal contents cannot enlarge that authority. Recovery
requires the trusted genesis, ordered authority extensions, current source profile
and expected complete journal digest from caller custody.

## Machine flow

A compound problem carries five typed parameters for `a*(b*x+c)+d=e`, a query
variable and optional source updates/definitions/result destination. Parameters
may be exact rationals, attested-source references or checked-derived references.

Before admitting a numeric compound call, the coordinator resolves each reference.
A current checked result is rechecked and bound without candidate generation.
A missing eligible result may create a real RPM child with an exact saved parent,
blocked reference, return address, resume stage, frame depth and remaining budgets.
The child proposes a value for an admitted definition; the checker validates it.
Successful admission and return resume the exact original caller. A failure must
unwind explicitly and retain its reason and spent work.

The existing compound construction, qualification, dispatch, original-expression
check and ordinary commitment gates still execute. If requested, storing that
committed result is a separate coordinator transition before final halt.
The stored result must bind its original problem, inputs, exact output, independent
check, execution record, commitment, source/derived dependencies and episode.

The initial acquisition grammar may explicitly refuse definitions that themselves
request derived references. It must never silently flatten an unsupported dependency
or turn an absent proof into a supplied value. Saved consumer results must still
retain and validate their transitive dependency closure.

Remembered rational numerators and denominators are bounded to128 bits. Runtime0.5
can compute wider intermediate/results; that does not permit admitting them into
this narrower result-memory contract. A support graph has at most16 records and
depth8, including the newly stored root. Missing-proof acquisition depth is one.

## Record and freshness requirements

A bounded derived record contains content and type, exact proof/provenance,
verification status, `NOT_CALIBRATED` confidence, logical creation/use positions,
immutable revision history, source links and a refresh policy. Logical positions
must name their episode as well as their tick; they are not wall-clock dates.

Freshness reconstructs the complete active source set for every reachable
dependency, not merely the continued presence of previously recorded hashes.
Correction, retraction, agreeing new revisions, newly conflicting sources, changed
definitions and incompatible checker/source profiles cannot reuse the old binding.
A different scope does not share a record merely because its numeric result agrees.

A stored consumer carries the exact producer revision and its transitive premise
closure. The dependency graph is bounded; cycles, missing witnesses, foreign
contexts and inconsistent duplicate identities refuse. A new head preserves the
old record as history. There is no implicit overwrite or provenance erasure.

Historical proof validity and present procedure-dispatch permission are different.
Rolling back a generator does not make a self-contained mathematical proof false.
It may prevent new execution; stale or revoked premises prevent present reuse.

## Verification and work accounting

Use protected `check_math_step` / `verify_math_receipt` and the unchanged exact
arithmetic rules. Do not label `verify_math_result` independent candidate
evaluation: that helper invokes the solver again. Reconstruct all equation,
variable, conclusion, source, scope and version bindings around a retained proof.

Expose candidate-generation attempts, retained-proof checks and new compound
dispatches separately. Conservative instruction/checker allowances are policy
units, not measured FLOPs, energy or money. Failed expensive work is charged.
No return, rejection, restart or new unresolved episode may refund a reservation.

A disabled generator must actually raise on any new invocation in reuse tests.
Historical recovery may re-execute past generation; that phase is reported
separately from the new continuation. No local neural/model or provider execution
is needed for this checkpoint.

## Required acceptance

1. Cold missing-result episode creates/returns the real prerequisite frame and
   solves the parent only after independent admission.
2. Producer `2*(3*x+5)+7=35` stores checked `x=3`. A later task supplies only
   its reference as `a` in `a*(2*y+1)+4=28`, yielding `y=7/2`.
3. During later-task reuse, candidate and procedure acquisition entry points are
   disabled. The trace names the exact stored revision and the new consumer check.
4. Authorize source correction5→8. Old producer and stored consumer results are
   stale. With generation disabled, the request refuses before execution.
5. Renew the producer through authorized checking, obtaining `x=2`; the later
   consumer yields `y=11/2` and records the new revision.
6. Wrong/resealed proofs, valid proofs for foreign inputs, wrong contexts,
   unsupported evidence requirements, new source conflicts, missing records,
   unauthorized heads, budget exhaustion and tampered saved parents refuse.
7. Another process reconstructs cut0 and every sealed event, including failures
   and post-commit/pre-store states, from external authority. Prefix and completed
   journals, state, trace, proposals, continuations and budgets match exactly.
8. All prior accepted source hashes/profiles and negative experimental evidence
   remain unchanged; run focused adversarial and appropriate full regression tests.

A passing engineering example proves only these covered behaviors. It does not
complete Phase3, general memory, CMB-R1, general procedure learning, language,
adaptive flow, tools, Foundry, evolution or the complete cognitive machine.

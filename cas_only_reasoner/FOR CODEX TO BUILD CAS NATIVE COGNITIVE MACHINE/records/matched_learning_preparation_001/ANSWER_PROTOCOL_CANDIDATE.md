# Candidate answer-protocol repair (not frozen)

This read-only source review proposes a separate bounded typed-answer study.
It is design work, not an implemented decoder, an admitted protocol or a new
learning result. Preserve existing evidence and use fresh initialization if this
proposal is adopted.

## Why public packet separation is insufficient

Canonical source menus depend on the answer before the packet is sealed:

- course.teaching_pairs uses direct_parts and traversal to shape candidates.
- face_tasks.content_for/compile_episode combines correct with authored negatives.
- ROLE_FROM_CONTENT includes the hidden role plus selected alternatives.
- adapter.public_records preserves correct during truncation to three options.
- The safe development-only builder intentionally preserves the legacy choices.

Mutating private targets after construction checks the packet boundary; it does
not prove answer-independent public construction.

## Proposed bounded public language

Keep every face, support, phase and logical presentation in the 1,152-event,
160-update-group schedule. Replace teacher-shaped three-choice menus with
model-produced values drawn from a public grammar:

| Task | Publicly defined answer form |
|---|---|
| Role recognition | Fixed six-role alphabet |
| Face 1 | Declared whole, kind and function references |
| Face 2 | Declared setting, participants and interactions |
| Face 3 | Candidate ID from a complete independently frozen public bank |
| Face 4 | Canonical correspondence pairs |
| Face 5 / graph questions | Canonical node-index sets or direct/absent/via-node |
| Face 6 | Branch account with order only where explicitly declared |

Bound the public node inventory, field references and output length before
admission. Publish tie and canonicalization rules. Check analogy-bank coverage
without silently dropping unmatched questions or inserting teacher-selected
candidates.

The public compiler accepts source facts, question, support records and grammar;
it receives no target, checker or negative-answer argument. Seal public content
before generating private corrections. The decoder may enforce syntax, but it
must not solve the problem or repair a wrong answer.

The source envelope must explicitly provide the facts needed to answer. Current
apply_problem contains the graph, while Face 1 also needs declared kind/function
and Face 2 needs setting information. Include those authored declarations,
correspondence and ordering constraints before removing the menu. These are
declared source facts, not independently established world truth.

This changes difficulty: the learner must construct an answer instead of
eliminating distractors. Scores and losses are not directly comparable with the
legacy three-choice profile. A new codec/decoder and numeric validation are
required. The existing exactly-three-observation interface and sum-pooled option
encoding cannot be assumed to preserve correspondence/order answers unchanged.

## Measurement proposal

Freeze before final scoring:

1. Learning speed: development checks at rounds 0, 4, 8, 12 and 16, exact-answer
   accuracy and loss against presentations, updates, decoder steps and actual
   compute. The threshold and evaluation work budget are chosen before results.
2. Gains/losses: current taught batch, other previously taught semantic questions,
   and support-only exposures reported separately. Semantic duplicates cannot
   become nominally independent other questions.
3. Transfer: application and earlier-skill recognition reported separately.
   Current application graphs combine topology and size change (8–10 versus
   3–4 nodes); preserve that limitation.
4. Retention: distinguish immediate competence, checkpoint reload persistence,
   and accuracy after fixed intervening teaching without rehearsal of the tested
   semantic questions. Existing maintenance rehearsal is not unrehearsed
   retention.

ALT versus MIXED can test order/grouping. The current ordinary-DAG control equals
ALT, so it is not a distinct treatment. WHOLE_SUPPLEMENT changes lesson content
and is a separate question.

Before model work, verify that teacher mutation cannot affect packet bytes or
answer vocabulary, all scheduled faces survive, complete declared source facts
survive encoding, and malformed/partial answers fail closed. Protect final
families and report actual compute equally in every arm.

THE ENCODER'S ENTIRE INPUT IS UNCHANGED.
  Every encoded vector, every score, and every recorded prediction's `scores` are
  therefore unchanged. What changes is plan_digest and the DECISIONS.

  So wiring the constraint layer does NOT invalidate the model, the encoder, the
  readout or the block, and it does NOT require a new baseline for them. Rounds 36
  and 37 described it as changing the contract and its digest, which is true, and
  implied that was expensive, which this measurement does not support.

Caveat: `binding.compile_packet` may itself read `slots.DECISION_CONTRACT`; it does not
here, which is what makes the encoder input invariant, but that is a property of the
current code and would need re-checking if the packet compilation changed.

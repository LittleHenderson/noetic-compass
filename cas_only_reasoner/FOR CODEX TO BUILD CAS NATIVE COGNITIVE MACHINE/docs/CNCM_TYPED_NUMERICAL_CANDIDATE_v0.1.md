# Typed numerical learner candidate v0.1

This extension implements the numerical encoder and learner as worker-only code.
It has not yet executed on CUDA. The separate source loader and full-course
admission contract are implemented; the new end-to-end worker and bounded launch
adapter still need integration. The complete machine and learning advantage are
not accepted by this delivery.

## Complete public input and fixed output

The encoder consumes the accepted reversible frame text and training-only
tokenizer, preserving all 64 worlds, declarations, relations, policies, query,
aliases and worked supports. The complete token sequence includes both markers.
Each JSON line has an explicit scope and ordinal. A seeded signed permutation
binds token position to its row. Frozen 64-wide token rows, field-query rows and
90 symbol readout rows are separately identified by exact bytes and source
profiles. Rows and aggregate vectors use the declared normalization rules;
zero/nonfinite norms are refused.

This is a finite 64-dimensional projection. It does not establish injectivity,
semantic understanding, geometric optimality or better learning. Pure binding
differences do not prove numeric separation. CUDA must measure row norms,
scope sensitivity and cache/direct agreement. Cache keys bind the complete
public packet and source/tokenizer/profile/row identities; no teacher filters
the input or syntactic answer universe.

The learner uses the existing registered `^6` operation, with 16,384 trainable
weights: left/right 64 by 64, merge 64 by 128. The pinned wheel's actual shape
corrected an initial source-draft error. No tensor ran during that correction.
The same `recurrence.run_passes` loop runs at declared depths 1, 2, 4 or 8,
starting at zero for every output slot. The input is reinjected each pass and
gradients remain connected through the complete loop. No checker chooses depth,
repairs predictions or selects only semantically correct candidates.

## Corrections and checkpoint boundaries

Public batch predictions and logits are produced before target access. The
caller must durably save the exact returned bytes; the learner compares that
file, its SHA-256 and current weights with its retained forward graph before
admitting private correction receipts. Synthetic test seals demonstrate this
contract only; they do not prove a model executed.

The private loss compiler independently checks all admissible answers. Mapping
loss is one normalized valid-set loss over complete bijections plus NO_MATCH,
not independent acceptable node marginals. Role ambiguity is an exact six-bit
target. Membership averages all binary slots, including absent members. Training
uses field means, then task means, then batch means. Alphabet-normalized losses
are reported separately. Forced single-choice fields are counted and have zero
loss. Tensor/scalar loss agreement remains a mandatory numerical check.

Checkpoints bind actual frozen rows, tokenizer, model, optimizer, parameter scope,
CPU/CUDA/Python random state, source profiles, counters and next-course cursor.
Restore must verify exact bytes and identities. The planned acceptance includes
same-process independent-module reconstruction and next-step replay. A future
fresh-process continuation is a separate claim.

## Source custody and proposed bounded run

The new standalone manifest loader must be bootstrapped from caller-verified
bytes before any `cncm` or `cas_meta2` import in a fresh process. It compiles exact
manifest-bound source bytes directly and does not load project bytecode caches.
Snapshots check loaded module objects, loaders, origins and current source bytes.
This is process-level evidence, not hardware/OS attestation. The separate pinned
wheel installed/loaded-source checks must also run.

The proposed engineering acceptance uses source seed 101 and
`ALT_COMPONENT_WHOLE`: all 564 distinct training packets, 1,152 presentations,
160 main updates and every answer kind/face. Its planned main work is 4,613 slot
calls and 17,178 recurrent core calls, excluding evaluation, replay and encoding.
Two separately counted validation replay steps raise the global update cap to
162. Model and encoder seeds are 20260916; these are new origins, with no reuse of
old three-choice checkpoints. The worker must explicitly seed each fresh model:
the older framework's seed argument alone does not do this.

AdamW settings are learning rate 0.003, weight decay 0.01, betas 0.9/0.999 and
epsilon 1e-8, with foreach/fused disabled. The proposed child wall limit is 1,800
seconds, one $7 reservation, no automatic retries. Actual encoder, checker,
training, evaluation, replay, transfer/hash overhead, memory and total time must
be measured. Partial completion is a failed/partial run, never a smaller pass.
The existing provider watchdog, price, budget authority and teardown controls
still require a new adapter; this document does not authorize a launcher bypass.

The package can retain the exact accepted 4,165,195-byte course and 447,140-byte
tokenizer within the existing 4 MiB member limit. Frames and slots are rebuilt
from public packet projections. Main targets are derived privately only after
prediction seals, avoiding the oversized private-target bundle. The course's
audit lineage never reaches the learner. Archive size and actual committed
package rehearsal remain open gates.

## Learning evidence remains open

Training on this course can establish the teaching connection and measure gains
and losses on exposed material. It cannot alone establish faster learning,
untouched-family transfer, delayed retention or a CAS advantage. Those require
the still-unfrozen matched comparison. The ordinary dependency graph currently
has the same order as component-first teaching; it cannot provide a distinct
ordering contrast without an explicit design change. The earlier three-seed
recurrence criterion remains NOT_MET, 0/3 positive.

The exact new pure checks and development limitations are recorded in
`records/typed_numeric_001/STATUS.md`. Older evidence remains unchanged.

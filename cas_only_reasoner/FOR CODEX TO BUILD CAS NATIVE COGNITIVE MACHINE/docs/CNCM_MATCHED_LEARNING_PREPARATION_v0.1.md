# Full-course preparation for a matched learning study

Status: PURE_PREPARATION_ONLY — MATCHED_STUDY_NOT_FROZEN.

This extension preserves the full authored course while preparing an honest
comparison. It does not execute training, construct final questions, establish
a learning benefit, or admit the legacy course to a protected final study.
The earlier input-v0.1 CUDA smoke and input-v0.2 completeness correction remain
separate evidence with their original source and publication identities.

## Equal-information schedules

`cncm/rpa_learning_match.py` compiles the existing source schedules for seeds
101, 202 and 303. Those numbers select source construction; they are not three
new model runs or a frozen choice of new model initializations.

Each schedule retains 1,152 presentations and 160 planned optimizer batches:
800 FACE_APPLY, 96 ROLE_FROM_CONTENT, 128 LIST_PARTS and 128 REACHED_VIA.
There are 624 distinct public inputs and 252 semantic questions. Repeated
presentations remain in their original schedule positions; only the cache
registry is deduplicated. The 896 common foundation/maintenance presentations
remain unchanged.

The component-then-whole and mixed controls have the same public lesson and
private correction multiset, batch sizes, update count and planned depth work.
Their actual teaching order/grouping differs. Actual compute is unmeasured:
matching a plan does not prove equal runtime, GPU work, encoding or overhead.

A third, ordinary dependency-graph scheduler explicitly links each component
presentation to its corresponding whole presentation. It changes only the 256
supplement presentations. With the current batch size of eight, its ready queue
produces exactly the component-then-whole update inputs. These are instructional
prerequisites chosen by the policy, not logical necessities of the questions.
This particular comparison cannot establish a CAS-specific benefit; it does not
prove that all possible CAS and graph policies are equivalent. A distinct
CAS-facing policy would need an operational definition and a fresh freeze.

## Keep support graphs bound to their context

The earlier ordered encoder sorts structural records globally. A retained
synthetic example swaps different relations between a support graph and a
current-task graph, leaving the framing text fixed. The public inputs differ,
but the old encoder compiles exactly the same frames.

The separate profile `cas.graph-scoped-ordered-problem-encoder/0.1` binds each
structural record to the preceding nonempty framing-line ordinal. That scope
enters every token-role permutation. Harmless reordering inside one context
remains invariant, while the tested cross-context swap produces unequal frames
and exact pre-normalization binding maps. The old encoder is unchanged.

These are pure map checks. They remove the demonstrated forced symmetry;
they do not prove universal collision freedom, numerical separation for every
finite projection, correct learned semantics or CUDA execution. The worker-only
factory exists but has not been numerically accepted in this stage.

## Full-course input boundary

`cncm/rpa_course_adapter.py` reconstructs every canonical training presentation
from pinned code. It retains every original source line and terminal-newline
state: structural node/rel lines remain structural, and other lines use an
escaped text representation. Each presentation receives the same explicit
complete-inventory statement. This assumption belongs to the authored complete
family graphs; it is not imposed on arbitrary narratives or the wider world.

A fresh tokenizer is fit on the exact deduplicated training publics, in a stable
order shared by the comparison arms. Binding requires the new scoped profile.
Private source selectors and teacher answers remain outside the closed prediction
packet: `record_id`, `public`, `encoded_options`. Separate source reconstruction
checks the teacher registry and its join to all scheduled presentations.

The retained binding example uses deliberately fictional projection and
checkpoint hashes. It proves contract behavior only. No numerical projection,
checkpoint, cache or worker is represented by those placeholders. Source profiles
pin files on disk; a future fresh-process worker must also check the actual
imported module origins and bytes before claiming execution provenance.

## Development construction without final questions

The separate development builder selects the canonical first six eligible
topologies using graph topology alone. It constructs 114 unique development
records with 120 panel memberships: 18 whole tasks, six component references
and 96 earlier-skill records. Component membership reuses existing records.

The old both-split builder and its target-constructing eligibility helper are not
used. Exact parity is checked against an isolated development-only prefix of the
old source. The final allocation is not generated, scored or frozen here.

Historical exposure limits remain. These 8–10-node development graphs differ
from the 3–4-node training corpus, so this is also size transfer. Two expanded
perspective variants overlap a development topology; they require exclusion or
family grouping if those variants are later reused. The canonical six/thirty
allocation itself remains disjoint.

## Remaining scientific and execution gates

The inherited multiple-choice construction still depends on target answers.
A public-only prediction packet does not cure answer-conditioned choice design.
Source preparation therefore remains explicitly unadmitted to the new ordered
study. Replace that design or freeze a clearly narrower, justified task contract
before protected final evaluation; do not silently trim away four cube faces.

A fresh course-aware predictor and paired worker initialization are still needed,
as are numerical scoped-encoder acceptance, actual source/parameter/cache
verification, saved public predictions before private scoring, and the final
protocol. The existing cube worker does not accept the new course packet IDs.

Report taught-question gains and other-exposed-question losses separately.
Measure learning speed against a predeclared competence threshold, transfer on
untouched graph families, and retention after fixed intervening teaching.
Demonstrate initial competence before calling a later score retention. Both
arms receive identical information and budgets; retain all failed runs and
count actual input, encoding, forward/backward and optimizer work.

Evidence is retained under `records/matched_learning_preparation_001/`.
The complete CNCM charter, matched neural learning gain and general learning
remain open.

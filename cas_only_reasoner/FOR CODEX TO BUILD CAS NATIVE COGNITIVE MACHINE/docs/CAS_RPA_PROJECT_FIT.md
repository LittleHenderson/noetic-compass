## First prototype

The prototype uses the real native missing-procedure episode already implemented
in runtime0.2, not the PDF's synthetic walkthrough. Its source-bound baseline is
records/native_procedure_001/acceptance_002:

1. An empty registry receives a=3,b=5,c=26, with no answer in the request.
2. The exact caller suspends, preserving goal, branch, input and return point.
3. A candidate is selected, independently qualified and installed by the kernel.
4. The saved caller resumes; its procedure produces7, the checker verifies it,
   and normal reasoning/comparison/commitment gates conclude.
5. A separate process recovers the journal and reuses the procedure to produce
   -3/2 on new inputs. Rollback then removes the active head and the next call
   refuses when acquisition is disabled.

The adapter reads a journal with a caller-trusted genesis and complete hash.
It semantically reconstructs that journal through the existing native
coordinator before creating any atlas nodes. It never imports the saved state
as authority or writes to a live machine. Recorded rejected transitions still
show their charged work and changed post-state hash. Coalesced ordinary batches
can be partially accepted; the view preserves accepted/rejected IDs separately.

The viewer provides a concept flower layout and an ordinary graph layout over
the same nodes, links, inspector and work budget. It has no execution, install,
rollback or network control. Its layout and focus controls change only the view.
This is an evidence inspection prototype, not yet a connected general planner.

## Namespaces and quantities kept separate

The current kernel declares CAS Drive IDs F1-F7 with labels matching the atlas's
DF1-DF7 Drive labels. This prototype does not install a cast between those
namespaces. The separate TKS TF1-TF7 and TF1a-TF7d namespaces remain opaque under
spec/FOUNDATION_DRIVE_ADAPTER_v0.1.md; the atlas cites a draft ontology rather
than a ratified replacement for that contract. No Foundation-to-Drive mapping,
28-channel allocation or D/W/P sufficiency is invented.

The native runtime's existing ^6 RECORD_DECOMPOSITION is a bounded logical
operation. Atlas contains_part is new descriptive bookkeeping; its presence
does not prove general native ^6 competence. ^5 Bias, ^8 association, ^9
conclusion, processing Domain E and Register |E retain distinct meanings.

No measured40-coordinate profile is available for this episode. It remains
unassigned. Optional exact-positive profiles in finite test fixtures must sum
to one and declare their basis; they are never probabilities or proof authority.
No ALR or Fisher-Rao geometry, CAS-Ohm routing, quantum behavior, physical
current or full 42-role board is added by this prototype.

## Evaluation and remaining work

Engineering checks compare typed expansion with an independent ordinary graph
walk using identical nodes, edges and budgets. They test shared witnesses,
conflicting versions, containment cycles, visible deferred work, exact caller
records, focus isolation, forged journals, failed-check charges and rollback.
This tests faithful representation and boundary preservation, not a performance
advantage over an ordinary graph.

A future benefit study must use held-out prerequisite failures and equal task
information/budgets. Measure correct missing-prerequisite diagnosis, wrong-node
or wrong-version actions, exact resumption, invalid-state leakage, work consumed
and human task time. Separately vary relation typing, recursive organization,
flower layout and any later routing policy. A favorable display alone is not
evidence of improved reasoning, learning or CAS-specific advantage.

General transition generation, learned planning, full board composition,
measured40-coordinate assignment and live write controls remain open. Native
kernel acceptance and current full-project requirement gates remain separate
from this viewer.

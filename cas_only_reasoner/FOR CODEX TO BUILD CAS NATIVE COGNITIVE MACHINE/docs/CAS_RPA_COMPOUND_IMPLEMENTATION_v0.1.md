# CAS-RPA projection of compound runtime 0.5

This contract defines a read-only evidence workbench for the actual compound
runtime. Current implementation, validation and publication evidence belongs in
`records/rpa_compound_001/STATUS.md`; this specification alone is not acceptance.
The earlier extension proposal and native 0.2 prototype remain immutable sources.

## Project fit and authority

The existing runtime constructs, qualifies, installs and invokes a finite call
program. This work exposes those different stages, the two acquisition frames,
the exact caller, source corrections, evidence and remaining work budget. It
advances the inspection and diagnosis portions of V08/V10/V13 and systems
8/9/24/27/31. It does not complete those requirements or the full V01-V18,
31-system and integrated 20-step charter.

The original atlas's relation contracts remain distinct: `contains_part`
describes constituents; `refines_state` supplies compatible detail;
`reachable_via` records or proposes a transition. View focus and hypothetical
branches remain distinct from the replayed current state. No rendered control
owns a coordinator, installs a program, commits an answer, writes source memory,
changes permissions, starts a task or performs an external action.

`compound_atlas_from_journal` requires a caller-trusted typed genesis, initial
source digest set, ordered ingress extensions, complete journal anchor and
runtime source profile. It invokes compound semantic recovery before exporting
any state as observed. Saved final-state objects do not bypass recovery. A
journal cannot supply its own source authority or substitute a final ingress
union for admission chronology. These are trusted-host custody boundaries;
neither hashes nor successful replay authenticate a human principal or world fact.

The outer document has version `cncm.rpa-compound-view/0.1` and five fields:
`schema_version`, `atlas`, `native`, `timeline` and `next_actions`. The atlas uses
the existing bounded typed model without changing its limits or namespace
semantics. The native section binds the runtime, current state, source profile,
ingress, complete journal and the original compound problem. Its named summaries
expose current-call state, parameters, frames, source history and bindings,
program/primitive identity, dispatch conditions and remaining budget.

## Historical evidence and present eligibility

A candidate being constructed, independently qualified, installed, available
for dispatch, successfully executed and finally committed are separate claims.
Removing the compound head prevents dispatch. Removing the authorized pinned
primitive also prevents dispatch even while the compound head and historical
artifact remain visible. Readiness hints are `PROPOSAL_ONLY`; they are diagnostic
necessary conditions and never execution permission.

Every timeline row retains original event identity, run, pre/post state,
proposed transition names, authorized and rejected identifiers, and committed
mutations. Both successful and rejected transitions can change the state hash:
an expensive rejected check may still consume its allocation. A partially
accepted ordinary batch remains partially accepted in the view.

Work reservations bind a physical record to its run, pre-event logical tick
and intent occurrence. The event's recorded logical tick is the post-event tick.
Duplicate or later stale proposals must not copy a prior allocation into another
event. Retained histories from earlier episodes must not be charged again in a
new episode. Conservative instruction/checker units remain separate from actual
primitive instruction/check counts, CPU time, energy and money.

Source assertions, corrections, retractions, scopes, source heads and exact
recall bindings remain inspectable. `TEST_FIXTURE` and `USER_ATTESTED` cannot
become independently verified factual claims through the viewer or arithmetic
checker. A checked output remains conditional on its original source bindings;
an executed call result is not automatically a committed final conclusion.

## Bounded catalog and navigation

The complete construction report is too large for an individual atlas field.
Keep its full immutable body once in a bounded evidence catalog, with original
report identity and every referring source-record digest. Atlas nodes contain
bounded summaries and exact references, not clipped source records. Original
journals remain separately retained and anchored.

Candidate paging binds report and record identity, range, page size, total and
remaining/deferred counts. Reject malformed or stale cursors and out-of-range
requests. An omitted candidate is not rejected, impossible or unverified by the
runtime merely because the display has not opened its page. A partial search
has its own actual candidate count and `SEARCH_EXHAUSTED` status. Display paging
cannot change that runtime status or its recorded search budget.

Flower and ordinary graph modes use identical canonical node/link data,
inspector evidence, relation filters and navigation limits. Directed expansion
counts the selected root as one node and records depth/node limits, revisits
and deferred work. Text filtering is a display operation, separate from graph
expansion. Neither operation changes the supplied current state, evidence,
registry, source bindings or execution budget.

The existing 512-node, 2048-link and 8 MiB atlas limits remain in force. The
outer document is limited to 32 MiB, with bounded structure and at most 20
candidates per display page. The catalog retains exact record/report identities.
Reject size
overflow rather than silently dropping events, source records or candidates.
A small display budget does not bound the independent cost of semantically
replaying a journal, including its finite construction work.

The HTML is standalone and offline. It has a restrictive content policy, treats
all source labels and values as inert text, and has no page network requests,
external execution controls or persisted machine state. Wire validation checks
shape, bounds and consistency; it is not equivalent to semantic recovery or
authentication of an arbitrary file edited outside this pipeline.

## Required evidence and limits

Acceptance must project all 75 pause points already retained for compound
acquisition/correction and typed failures, under the unchanged actual runtime
profile. It must retain examples of both active acquisition frames, a constructed
but uninstalled program, installed state awaiting return, the checked solution,
later source correction/reuse, both rollback cases and bounded search/budget
failure. Separate tests cover wrong anchors, ingress chronology, forged and
resealed histories, stale/duplicate charges and report/cursor tampering.

An independent ordinary graph traversal checks exactly the same input graph,
root, relation set, depth and node budget. Browser tests check both layouts,
focus, filtering, expansion, candidate pages, exact evidence inspection, source
immutability, hostile text, readable labels, narrow-screen bounds and no page
network requests. Original runtime profiles and the earlier RPA receipt-bound
source files must remain byte-identical.

This establishes evidence presentation and boundary preservation only. No native
40-coordinate measurement, probability model, general nerve/sheaf construction,
Foundation-to-Drive cast, quantum behavior, physical current, general learning
or advantage over an ordinary graph follows. A held-out human/engine benefit
study with equal information and budgets remains a separate open requirement.

### 1b. Eight defects fixed (each with a regression test)

1. A relation is now found in a relation set (`R1 ∈ {R1}` was always false).
2. A ring result in a set has a readable label built from every term with its own Domain, Drive and Register (`Phi<^8^C_{F2}|A:^3^C|f>`, was a raw Python repr) and is found again; two nestings that differ in order, in a term's Domain, Drive or Register are different elements.
3. **Withdrawn after review, left for the owner.** A version that keyed a set-as-element by its contents was built and then taken out: the reviewers showed it made a typed set equal an untyped set with the same members, turned an untyped literal into a built-in with the same members (`{T, A, f, E}` became `Registers`), changed `CoverOf` family sizes, and flipped `"CO-2" ∈ Noetics` from true to false. A set used as an element is therefore still known by its binding name (`Beta ∈ {Alpha}` is false even when Alpha and Beta have the same members, and the text `"Alpha"` can still forge it). Whether two differently named sets with the same members are ONE element is decision "set identity" in section 5.
4. A tuple is now found in a `Product` set (both sides use the label `Tuple<a,b>`).
5. Names that start with `P`, `C`, `E` or `O` are whole words (`Cluster{…}`, `EmptySet`, `Charlie`, `CASTuple` no longer split into a Domain letter plus a leftover).
6. Cardinality bars around a call or a set expression parse: `|Product(Noetics, Domains)| = 40`, `|Noetics ∪ Noetics| = 10`.
7. A chained comparison (`A ⊆ B ⊆ C`) gets a clear error instead of a wrong type error. Real chaining needs an *and*, which the language does not have.
8. Deep input (about 180 bracket levels, or a flat chain of 1,000 terms) gives a CAS error instead of a raw Python crash, and no unserialisable tree is kept; reserved names (`C`, `A`, `Noetics`, `Worlds` …) are refused as `let` names and parameter names with a message that lists what is reserved (before, `let A = …` silently returned the register symbol) — **function names are not reserved**, because `fn f(...)`, `fn A(...)`, `fn Noetics(...)` always worked correctly (a call looks the function up by name); the parse tree is kept when a later stage fails.

**Not changed, listed for the owner:** the ring's same-Domain rule was enforced on one path only (the hole the examiners found: an any-typed parameter or `fractal(...)` slipped past it). It is now gone on every path, because the book nests across Domains; a warning is raised on every ring type-check path when both sides' Domains are known and differ; the whole's legacy `domain` field is still picked by position (open question N8), and for a bare-Noetic word such as `CO-8 ∘ CO-3` it reads `P` (pre-existing; the `nesting` block reports `domain: None` for such terms).

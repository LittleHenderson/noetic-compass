## The checkpoint identity distinction is now settled

The audit’s explanation supports the distinction we needed:

**Checkpoint identity** answers: “Is this the particular saved artifact I intended to load?”

**Semantic digests** answer: “Do these runs agree on the particular program, model, or semantic projection represented by those digests?”

Two independently created checkpoints can represent equivalent computation while having different artifact identities because their run UUIDs differ.

Therefore, the correct independent procedure is:

```text
Create checkpoint A
→ preserve A’s issued digest
→ resume A using A’s digest
```

It is not:

```text
Create checkpoint B
→ try to validate B using checkpoint A’s digest
```

There is no reason to remove the UUID or weaken the identity guard merely to make independently created checkpoint hashes equal.

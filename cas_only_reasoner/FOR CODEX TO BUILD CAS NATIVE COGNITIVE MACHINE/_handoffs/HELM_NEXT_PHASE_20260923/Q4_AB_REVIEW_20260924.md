### BLOCKER / MAJOR

#### Finding 1 (MAJOR)

- **severity:** MAJOR
- **summary:** ARCHITECTURE_CHANGE_JUSTIFIED can fire even when the model does read its input. INPUT_USE_DETECTED needs T1 and T2 and T3 together, and JUSTIFIED is triggered by 'not detected'. So a model that uses its input only partly, or only with the correct previous tokens, is counted as 'no input use'.
- **file:** cas_only_reasoner/FOR CODEX TO BUILD CAS NATIVE COGNITIVE MACHINE/research/helm_cas_expression_lab/read_q4_ab_results.py
- **line:** 171 (the conjunction); 250-262 (arm_status); 353-359 (the architecture label). Spec Q4_SDG_AB_SPEC_v0_2.md sections 7.1-7.3, lines 162, 203-211
- **scenario:** Measured, $0, pure Python. I ran the runner's own evaluate() and the reader's input_use() on a fake model called TF_READER_FREEGEN_COLLAPSE. Given the correct previous tokens, it reads every field: T1 799/799, T2 773 up and 0 down. Its first free decision is always STATE, so free generation gives 1 distinct output and T3 fails. Result: INPUT_USE_NOT_DETECTED. If all 6 runs look like this, the reader prints ARCHITECTURE_CHANGE_JUSTIFIED. That conflicts with two texts. (1) The owner's decision: 'If neither arm shows input use'. This model shows input use. (2) Directive section 3: when behaviour differs with correct previous tokens, 'investigate that training/generation difference rather than blaming capacity alone'. The same thing happens to a model that reads domain, drive and register values but not the Noetic (T1 fails, T2 passes): the label is JUSTIFIED. There is a third path. arm_status marks an arm DOES_NOT_SHOW when detected runs plus invalid runs is less than 2. So one fully detected seed in each arm (2 of 6 runs) still gives JUSTIFIED, although one detected run already shows the architecture can carry the input. If each seed has a 0.5 chance of detection, JUSTIFIED fires 25% of the time (0.5 x 0.5).
- **fix:**
  - Grade each FINAL run into levels, with T2v = T2 computed on same-length value edits only:
  - - FULL = T1 and T2v and T3.
  - - TEACHER_FORCED_ONLY = (T1 or T2v) and not T3.
  - - PARTIAL_FIELDS = T2v and not T1.
  - - NONE = neither T1 nor T2v.
  - Then:
  - - ARCHITECTURE_CHANGE_JUSTIFIED only if every valid run of both arms is NONE, with at least 2 valid runs per arm.
  - - ARCHITECTURE_CHANGE_NOT_JUSTIFIED as now (some arm FULL in at least 2 of 3 seeds).
  - - Everything else is ARCHITECTURE_DECISION_INCOMPLETE with a named reason: TEACHER_FORCED_ONLY, PARTIAL_FIELDS or SEED_DEPENDENT.
  - Add reader tests using these two fakes. Freeze only after that.

**Disposition: FIXED, with four disclosed changes to the proposed fix.**
- What was done, as proposed:
  - T2V = the one-field-edit test on the **538 value edits** only (54 rises needed).
  - Levels FULL, TEACHER_FORCED_ONLY, PARTIAL_FIELDS, NONE, graded per run and checkpoint (`q4_ab_rules.input_use_level`).
  - JUSTIFIED only when every valid FINAL run of both arms is NONE, with at least 2 valid runs per arm.
  - NOT_JUSTIFIED when some arm is FULL in at least 2 of 3 seeds.
  - Otherwise INCOMPLETE with named reasons, including SEED_DEPENDENT (`q4_ab_rules.architecture_decision`).
  - Reader tests with both fakes, built from the runner's own `evaluate()`.
- Changes to the proposed fix, and why:
  1. **A fifth level, STRUCTURE_ONLY.** Under the proposed definition, the reviewers' own STRUCTURE_ONLY fake (MINOR 1)
     would be graded NONE, so six such runs would give JUSTIFIED. That model reads its input (shape, operators, field
     presence), so it is the same defect. New test T2P = the same edit test on the **235 presence edits** (24 rises).
     STRUCTURE_ONLY = not T1, not T2V, and T2P. NONE now also needs T2P to fail.
  2. **A complete partition.** The proposed list leaves out (T1, not T2V, T3). It is now PARTIAL_FIELDS ("T3 and exactly
     one of T1, T2V"). The proposed list also puts (not T1, T2V, not T3) in two levels. It is now TEACHER_FORCED_ONLY
     (the levels are checked in order). A test checks all 16 combinations of the four tests.
  3. **The calibration guard** now fires if any run's checkpoint-0 level is not NONE (it used to need all of T1, T2
     and T3). T3 alone may pass on an untrained model; it does not change the level.
  4. **Names.** The negative label is `ARCHITECTURE_CHANGE_NOT_JUSTIFIED_BY_INPUT_USE_RULE` (see MINOR 5). The arm label
     `ARM_x_DOES_NOT_SHOW_INPUT_USE` became `ARM_x_SHOWS_NO_INPUT_USE`, because its meaning changed.
- Evidence (measured, pure Python, on the runner's own `evaluate()`, both arms). Each cell is a value the passing

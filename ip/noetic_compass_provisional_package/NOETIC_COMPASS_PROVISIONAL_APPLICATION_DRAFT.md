## Field

The invention relates to computer-implemented systems for evaluating output generated by artificial-intelligence systems. More particularly, it relates to:

- staged machine assessment pipelines
- provenance-aware scoring systems
- external scorer versus generator separation
- human-machine calibration workflows
- benchmark evidence logging and review

## Background

Existing AI evaluation systems frequently suffer from one or more of the following technical deficiencies:

1. They reduce a generated output to a single scalar score with poor auditability.
2. They fail to preserve whether a score came from deterministic heuristics, self-reporting by the generating model, or a separate scoring model.
3. They conflate generation and evaluation, causing the same model to effectively grade itself.
4. They do not preserve structured disagreement evidence from human raters.
5. They mix different evaluation modes into one ranking table, making benchmark comparisons misleading.
6. They provide little durable infrastructure for storing scorer-agreement cases, false-positive/false-negative cases, benchmark runs, and calibration decisions.

There is therefore a need for a computer-implemented system that can:

- assess AI outputs in multiple ordered stages rather than one opaque step
- preserve scoring provenance
- separate generator and scorer roles
- support multiple scoring modes without confusing them
- maintain a human reconciliation and evidence record
- produce auditable, exportable results suitable for later validation review

## Summary of the Invention

In one aspect, the invention is a computer-implemented assessment system that receives a prompt, obtains a generated response from an AI model, evaluates the response through a plurality of ordered scoring and integrity stages, computes a composite output, and returns the result together with scoring provenance.

In another aspect, the invention provides selectable scoring modes, including:

- a deterministic heuristic mode
- an external secondary scorer mode
- a self-reported inline scoring mode

In another aspect, the invention records whether scoring was produced by heuristics, a separate scorer, or the generator itself, and surfaces that provenance in both internal data structures and user-facing reports.

In another aspect, the invention provides a human-machine calibration subsystem that:

- identifies disputed items
- presents panel and machine scores together
- allows a reconciler to record a disposition
- optionally stores reconciled scores
- preserves durable calibration history

In another aspect, the invention provides an evidence subsystem that stores and reviews:

- scorer-agreement cases
- benchmark-suite runs
- false-positive cases
- false-negative cases

In another aspect, the invention separates benchmark rankings by scoring mode so that a neutral heuristic baseline is not merged with a model-as-judge or external-scorer comparison.

## 2. Exemplary Inputs

The system accepts one or more of the following:

- prompt text
- generator provider identifier
- optional generator model identifier
- dial configuration values
- scoring mode selection
- optional scorer provider identifier
- optional scorer model identifier
- human validation labels
- calibration notes and reconciliation dispositions
- benchmark suite definitions and prompt collections

In the current implementation, a request object includes explicit scoring controls through fields such as `scoring_mode`, `scoring_provider`, and `scoring_model`.

## 3. Multi-Stage Assessment Pipeline

In one embodiment, a pipeline runner receives the prompt and executes a sequence of ordered stages.

### 3.1 Input analysis stage

The system analyzes the input prompt and extracts structured information used downstream.

### 3.2 RPM gate stage

The system computes prerequisite or integrity-related features before or alongside generation. In the current implementation this stage produces RPM-related intermediate values and integrity scores.

### 3.3 Dial adjustment stage

The system applies configurable dial values or sensitivity controls that affect how the subsequent scoring pipeline weights or interprets the response.

### 3.4 Base generation stage

The system sends the prompt to a selected generator provider and receives a generated response.

### 3.5 Operator scoring stage

The system scores the generated response according to a selected scoring mode. This stage is important because it does not require one fixed evaluator.

### 3.6 Domain coherence stage

The system converts operator-level signals into higher-order grouped coherence values.

### 3.7 Inversion scan stage

The system evaluates risk, inversion, or instability axes and may compute additional resistance-related values.

### 3.8 Output stage

The system produces:

- sub-scores
- composite score
- tiered output classification
- provenance information
- optional interpretation and analysis data

## 4. Scoring Provenance and Mode Separation

This is one of the strongest technical aspects of the invention.

The system supports multiple scoring modes, including:

### 4.1 Heuristic fallback mode

A deterministic structural scoring path is used without asking a model to score the response. This is the least-biased automated baseline in the current product protocol.

### 4.2 Secondary scorer mode

A separate scorer model is invoked to assess the generated response. The scorer may be a different provider or model than the generator. The system records which scorer was used.

### 4.3 Self-reported mode

The generator may be permitted to emit inline self-scores, but this path is treated as distinct from both heuristic and external-scorer operation.

### 4.4 Provenance output

The system stores and surfaces:

- requested scoring mode
- actual scoring method used
- scorer provider
- scorer model

This provenance is preserved in machine output and surfaced in reporting/export layers so that downstream users can distinguish self-assessment from independent scoring.

## 5. External Scorer Resolution

In one embodiment, when `secondary_llm` is requested, the system attempts to resolve an external scorer provider that is different from the generator provider when one is available.

If the preferred scorer fails or is unavailable, the system may:

- fall back to a same-provider scorer according to policy, or
- fall back to deterministic heuristics according to policy

The important point is that the system records what actually happened rather than hiding the scoring path.

## 6. Human Validation and Calibration

The invention further includes a human validation subsystem.

### 6.1 Human labels

Human raters score prompt-response items using a defined rubric and submit structured labels.

### 6.2 Disagreement identification

The system identifies items with multiple human ratings and detects disagreement between:

- human raters
- human panel means
- machine scores

### 6.3 Calibration session

In one embodiment, the system presents a calibration queue that includes:

- disputed item identifier
- prompt
- response
- machine profile
- panel profile
- largest-gap operator
- prior calibration-session count

A reconciler may then enter:

- a disposition
- explanatory notes
- optional reconciled operator/domain scores

The system stores this session durably for later audit.

## 7. Evidence Logging and Review

The invention further includes an evidence subsystem.

### 7.1 Evidence categories

In one embodiment, the evidence subsystem stores at least:

- scorer-agreement cases
- benchmark-suite runs
- false-positive cases
- false-negative cases

### 7.2 Review and export

The system supports:

- filtered evidence review
- provider/model summaries
- trend summaries over time
- export to machine-readable formats

### 7.3 Benchmark separation

The system keeps scoring modes separate in stakeholder-facing rankings.

For example:

- one table for heuristic baseline
- one table for external-scorer runs

This avoids misleading comparisons caused by mixing structurally different evaluation modes.

## 10. Example Technical Workflows

### Workflow A: Single prompt assessment

1. receive prompt
2. select generator and scoring mode
3. generate response
4. score response
5. compute composite output
6. return provenance-aware result

### Workflow B: External scorer assessment

1. receive prompt
2. select generator provider A
3. resolve scorer provider B
4. generate response with provider A
5. score response with provider B
6. store scorer provenance
7. present result and export

### Workflow C: Human calibration

1. collect multiple human labels
2. identify disagreement cases
3. queue disputed items
4. present human and machine deltas
5. record reconciliation decision
6. preserve calibration history

### Workflow D: Stakeholder benchmark reporting

1. run frozen prompt set in heuristic mode
2. run same prompt set in external-scorer mode
3. store results separately
4. display separate ranking tables
5. reconcile disagreement cases through human review

- [ ] Confirm the human inventor(s) for the Noetic Compass system claim family
- [ ] Separate conception from implementation labor
- [ ] Confirm whether any collaborator, contractor, or coauthor contributed to the claimed technical system
- [ ] Prepare a dated inventorship note explaining who conceived:
  - [ ] the staged wrap pipeline
  - [ ] the multi-mode scoring/provenance system
  - [ ] the calibration-session workflow
  - [ ] the evidence logging / benchmark separation system

## 2. Public Disclosure Timeline

- [ ] Confirm earliest public date for `https://noetic-compass.vercel.app/`
- [ ] Confirm earliest public date for `https://github.com/LittleHenderson/noetic-compass.git`
- [ ] Confirm earliest public date for any public manuscript or PDF
- [ ] Confirm earliest date any stakeholder deck/demo was shown without NDA
- [ ] Confirm whether any benchmark exports or screenshots were shared publicly

Do not leave these as guesses.

## 3. Filing Scope Decision

- [ ] Confirm this filing is limited to the **Noetic Compass system**
- [ ] Decide whether to exclude CAS theory/philosophy from the filing narrative except as background
- [ ] Decide whether to keep the CAS-native architecture and compiler/toolchain out of this first filing
- [ ] Decide whether to reserve some heuristics or operational details as trade secrets

## 6. Filing Questions For Counsel

- [ ] Should this be filed first as a provisional?
- [ ] Is the current disclosure history still safe for U.S. filing?
- [ ] Is any non-U.S. protection already impaired?
- [ ] Should the claims focus on:
  - [ ] staged assessment pipeline
  - [ ] provenance-aware scoring
  - [ ] calibration/reconciliation workflow
  - [ ] evidence logging / mode-separated ranking
- [ ] Which terms should be generalized to avoid abstract-idea problems?
- [ ] Which product terms should remain implementation examples only?

## 7. Draft Cleanliness Check

- [ ] No unsupported scientific claims
- [ ] No claim that heuristic signals are validated instruments
- [ ] No claim that the filing covers the abstract CAS theory itself
- [ ] No statements that accidentally narrow the invention to one provider
- [ ] No statements that accidentally require the UI to exist when the core system could be server-side only

## 8. Pre-Filing Do-Not-Do List

- [ ] Do not publish new technical architecture details before counsel review
- [ ] Do not post new screenshots or benchmark claims publicly
- [ ] Do not claim "patent pending" before filing
- [ ] Do not treat AI-generated draft text as a substitute for counsel review
- [ ] Do not broaden public disclosure while dates are still unconfirmed

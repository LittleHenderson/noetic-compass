# Counsel Handoff Checklist

Use this before sending the CAS-native provisional package to patent counsel.

## 1. Inventorship

- [ ] Confirm the human inventor(s) for the CAS-native architecture claim family
- [ ] Separate conception from implementation labor
- [ ] Confirm whether any collaborator, contractor, or coauthor contributed to the claimed technical system
- [ ] Prepare a dated inventorship note explaining who conceived:
  - [ ] the 40-slot cognitive-state architecture
  - [ ] slot-level domain-descent attention
  - [ ] structured CAS-label supervision
  - [ ] CAS-engine scoring integration
  - [ ] any compiler/language coupling intended to be claimed

## 2. Public Disclosure Timeline

- [ ] Confirm earliest public date for any public repository containing `cas-native`
- [ ] Confirm earliest public date for any PDF or manuscript describing the CAS-native model
- [ ] Confirm earliest public date for any demo, benchmark, or deck shown without NDA
- [ ] Confirm whether screenshots, architecture diagrams, or benchmark charts were shared publicly
- [ ] Confirm whether any language/compiler materials were public before the model disclosure

Do not leave these as guesses.

## 3. Filing Scope Decision

- [ ] Confirm this filing is limited to the **CAS-native architecture**
- [ ] Decide whether to exclude CAS theory/philosophy from the filing narrative except as background
- [ ] Decide whether to keep Noetic Compass system claims out of this filing to reduce overlap
- [ ] Decide whether the compiler/toolchain linkage is part of this filing or a separate family
- [ ] Decide whether some training heuristics or operational details should remain trade secrets

## 4. Figures and Exhibits To Prepare

- [ ] Figure 1: overall CAS-native model architecture
- [ ] Figure 2: 40-slot cognitive-state branch and token-to-slot aggregation
- [ ] Figure 3: slot-level domain-descent attention flow
- [ ] Figure 4: prerequisite gate / RPM pathway
- [ ] Figure 5: training path from CAS labels to 40-state target distributions
- [ ] Figure 6: evaluation path from model output into Rust CAS engine scoring
- [ ] Figure 7: optional compiler/language integration path
- [ ] 2-4 architecture diagrams from the current implementation
- [ ] 1-2 benchmark or evaluation artifacts
- [ ] 1 example showing masked-token invariance or slot-level behavior

## 5. Evidence To Preserve

- [ ] Current code snapshot / commit hash
- [ ] Model architecture notes and diagrams
- [ ] Tests for slot-level domain-descent, padding-mask invariance, and CAS-label supervision
- [ ] Evaluation artifacts showing Rust engine integration
- [ ] Any early sketches or notes showing conception dates
- [ ] Any presentations or internal notes that mention the 40-slot architecture

## 6. Filing Questions For Counsel

- [ ] Should this be filed first as a provisional?
- [ ] Is the current disclosure history still safe for U.S. filing?
- [ ] Is any non-U.S. protection already impaired?
- [ ] Should claims focus on:
  - [ ] fixed 40-slot latent structure
  - [ ] slot-level domain-descent attention
  - [ ] CAS-label supervision path
  - [ ] engine-aligned scoring/evaluation
  - [ ] compiler/language integration
- [ ] Which terms should be generalized to reduce abstract-idea or printed-matter risk?
- [ ] Which names should remain implementation examples only?

## 7. Draft Cleanliness Check

- [ ] No unsupported claims that the model is a validated cognitive science instrument
- [ ] No claim that the neural approximations are mathematically identical to the full formal system unless actually enforced
- [ ] No claim that the filing covers the abstract CAS theory itself
- [ ] No accidental narrowing to one foundation model, one training corpus, or one deployment path
- [ ] No suggestion that heuristic risk signals are fully validated instruments

## 8. Pre-Filing Do-Not-Do List

- [ ] Do not publish new architecture details before counsel review
- [ ] Do not publish new benchmark claims publicly without confirming filing timing
- [ ] Do not claim "patent pending" before filing
- [ ] Do not treat AI-generated draft text as a substitute for counsel review
- [ ] Do not broaden public disclosure while dates are still unconfirmed

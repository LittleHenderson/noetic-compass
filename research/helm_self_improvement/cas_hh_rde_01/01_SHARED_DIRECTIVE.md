## 1. Foundational instruction: one parent, different configurations

CAS Harness and HELM derive from the same CAS parent/framework and use pieces of that parent in different arrangements for different purposes. Treat their connection as a configuration-aware integration within the CAS family, not as an unrelated generic observability product being bolted onto HELM.

The owner identifies CAS Harness's existing detection of neuron groups/configurations that respond to inputs as the starting capability. Reuse its implemented capture, configuration/readout, intervention, and evidence machinery. Do not restart the historical detection project or replace it with a second generic logger. Attach the applicable source and experiment references to reused capabilities; source existence, reported prior results, independently checked results, and HELM-specific validation remain distinguishable.

Common parentage is a reuse and semantic-alignment advantage. It is not an assumption that different models have identical hidden-coordinate meanings, compatible tensor shapes, the same learned weights, or interchangeable probes. A shared framework also need not mean the two export repositories share an intact Git history. Preserve actual ancestry and export provenance without fabricating it.

A detected configuration can be a set of coordinates, a distributed feature direction, a learned subspace, or a pattern across execution rounds. Record what was actually measured. In particular, a projected MLP-output coordinate must not be renamed as an individual hidden MLP neuron merely because the UI draws it as one.

## 3. Mission and first finish line

Build an executable bridge from:

**permitted stimulus -> actual HELM activity -> detected configuration -> explicit causal hypothesis -> bounded intervention and matched controls -> independently scored task effect -> retained research evidence -> one targeted improvement candidate when justified.**

First engineering finish line: one admitted HELM input runs with the existing Harness attached; original prediction and scoring path are preserved; actual capture coverage is recorded; a no-op control is neutral; one declared intervention is executed and accurately recorded; exact caller/branch identities survive; and the evidence reloads into the existing RPA view. A null or harmful intervention is a legitimate completed result. An injected fault is labeled injected, not a discovered natural defect.

First research finish line: a small predeclared investigation identifies a reproducible causal contribution or rejects a specific hypothesis about Parts/Reach performance. It does not need to explain every weight before being useful.

First development finish line: if evidence warrants it, implement ONE remedy that does not need the correct answer at inference time, then compare it with its unchanged parent and an appropriate simple alternative. Improved probability margins, corrected system outputs, raw model accuracy, and learned self-improvement are separate endpoints.

## 5. Research sequence

### R0 — Configuration-aware reuse, one short implementation-oriented pass

Extend the existing source manifest with the CAS parent definitions/version/hash, concrete component imports, local adaptations, and the relevant Harness/HELM interfaces. Classify a relationship as exact shared implementation, versioned adaptation, semantic correspondence, or unknown. Canonical CAS meanings are not edited to fit activation clusters. Do not invent a global one-to-one neuron-to-CAS-label map.

Record accessible Git commits or a bounded export for Claude. Windows-only paths are not a cloud handoff. Do not search all branches, reconstruct unavailable history, or read protected material to resolve imports. If a field is unavailable, block only its dependent claim, not unrelated adapter code.

### R1 — Baseline-neutral capture

Codex exposes actual HELM connection points to the existing Harness. Start at the Parts/Reach path: public input mapping, graph-round inputs/states/updates, query and node representations, node_head, reach_option_head, node-pointer scores, decision, and answer assembly.

Record stable tensor/site identifiers, dimensions, dtype/device, coordinate meaning, round index, input and checkpoint identities, actual call counts, signed values or bounded tensor references, missing coverage, and overhead. Keep enough admitted representation for the proposed analysis; a top-K positive-activation display is not a complete causal dataset.

Capture is disabled by default and observation-only. In a fixed supported environment, compare uninstrumented and observed copies with the same initial state: prediction, score arrays, model/optimizer state, RNG, cache effects, and hook removal. Use exact equality where justified; preregister any numeric tolerance. Wall-time overhead must be charged rather than hidden. Never return changed tensors from a passive hook.

A hook failure may allow the learner to finish, but the diagnostic receipt must become incomplete; never silently report full coverage. Bound capture bytes and detach stored tensors so computation graphs cannot accumulate indefinitely.

### R2 — Stimulus-responsive configurations and CAS readouts

Use existing Harness detectors/readouts where compatible; reuse algorithms and evidence infrastructure, not blindly transferred probe coefficients. Fix feature coordinates and CAS labels from the discovery/training split only. Independent probe training, if needed, is separately identified and metered.

Test stability/selectivity against permitted stimulus changes, label-shuffled or metadata/input-only baselines, and a capacity-matched generic semantic partition where a CAS-specific advantage is claimed. Do not train the readout on the final confirmation cases or let it learn the answer and attribute that achievement to HELM.

Retain coactivation and inhibition, not just high-amplitude positive signals. A CAS-correlated configuration is a finding at the readout level; its contribution to the final task must be tested next. Shared CAS parentage motivates the mapping; its fidelity on HELM is measured.

Split by underlying structures/families, not random rows from the same graph. The existing 59-question development set covers six selected structures and is not an untouched final examination. New synthetic/public diagnostic fixtures must be labeled as such. Rule-sensitive relabelings must respect the lexical Reach tie-break: either preserve it or recompute the expected mapped answer in the evaluator; do not assert a false renaming invariance.

### R3 — Causal contribution to the answer

Freeze at most two hypotheses and four candidate configurations in the initial pilot. Each names target site, intervention, sign/magnitude, predicted change, matched controls, outcome metric, cases, and stopping rules before confirmation results.

Begin with within-checkpoint interventions. Use NO_OP, one bounded suppression/patch operation, and an appropriate same-size/rank/norm control; sham edits must have the same instrumentation overhead. Confirm the target was actually reached and modified before scoring the task output. A failed intervention must not be silently replaced with no-op success.

Measure actual Parts/Reach scores and checked answers, alongside CAS readouts. Loss of probe accuracy alone is not evidence of loss of task computation. Association, contribution/necessity, limited rescue/sufficiency, and full algorithmic explanation are distinct. A loss after ablation can reflect nonspecific damage; matched controls and replication distinguish it.

Same-shaped vectors from different checkpoints are not assumed semantically interchangeable. Cross-checkpoint or correct-example donor patches need an explicit compatibility hypothesis. Gold-informed donor choice is a diagnostic/oracle-assisted experiment, not deployable correction or native reasoning.

Do not confuse the exact chronological execution trace with an explanation of the learned algorithm. A claim of an exact mechanism requires an executable account and tested counterfactual predictions over its declared domain.

### R4 — Targeted strengthening or repair

Choose one supported remedy based on the causal result: a verified software fix, improved routing/representation, targeted teaching, altered learning settings, or capacity at the relevant active path. NO_CHANGE and retraining existing capacity remain eligible.

Do not indiscriminately scale all active neurons. Predefine any gain range, norm/finite checks, scope, and rollback. Direct runtime steering, changed training, architectural growth, and structured input conditioning are different interventions with different attribution and cost.

A world_head-only change is not assumed to directly improve Parts/Reach; inspect actual execution dependencies. Shared-parent semantics may support a structured conditioning bridge, but a natural-language prefix cannot be declared effective when HELM's actual reader ignores it. A compiler or verifier supplying the correct answer is not model improvement.

Keep original raw predictions, after-intervention predictions, verified system outputs, coverage, regressions, costs, and failed attempts. Confirmation cases may not determine candidate selection. Retain the candidate only for research unless all existing separate promotion gates pass.

### R5 — Reusable experience, not premature autonomy

Map the admitted episode to existing HELM-SI-1 records. Record who detected, hypothesized, selected, implemented, verified, and retained. This wave is externally directed unless HELM demonstrably made a particular decision. Do not label an external-agent fix native self-improvement.

RPA shows the recorded configuration, alternative hypothesis, intervention, result, and lineage. Harness harvest/corpus ingestion remains disabled for these research traces unless its exact data permission and split are recorded. No customer data, production credentials, or automatic ingestion of development/final feedback into training.

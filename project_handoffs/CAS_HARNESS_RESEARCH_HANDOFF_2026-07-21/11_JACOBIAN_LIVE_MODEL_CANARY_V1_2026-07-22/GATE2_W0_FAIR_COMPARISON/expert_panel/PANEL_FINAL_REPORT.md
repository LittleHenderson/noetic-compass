## 1. THE ANSWER IN THREE SENTENCES

All four experiments failed because they were aimed at the wrong gate — prompt-injection detection is `Gate 3` item 8 in the controlling roadmap, and the word "injection" appears zero times in `Gate 2`'s eight items — so four honest failures on a `Gate 3` deliverable could not move `Gate 2` in either direction. Within that wrong target, the dataset chosen makes the answer readable straight off the page: the label is a one-bit substring property of the prompt, hidden only behind an encoding the prompt itself announces in plain text, so decoding it and running the project's own feature code scores `0.9250` against a best-ever internal-state score of `0.7375`. That means the four `FAIL` verdicts understate the result — this is not a near-miss at a hard bar, it is a significantly negative result whose error bars sit entirely on the wrong side of zero, and it was already established five weeks ago on a bank four times larger.

Definitions used throughout: **balanced accuracy (BA)** = the classifier's accuracy averaged over the two classes, so `0.5000` is chance. **Probe** = a small linear classifier trained on the model's internal numbers. **Control** = the same classifier trained on something that does *not* require the model to have understood anything (raw text features, character chunks, the model's untouched input embeddings). **Margin** = internal-state BA minus the strongest control's BA. **Pre-registration** = writing down the pass/fail rule before seeing the result.

## 2. WHAT THE PANEL AGREED ON

Every point below was independently verified by at least two reviewers against files on disk, not inferred.

**a. The four experiments answered `Gate 3`'s question, not `Gate 2`'s.**
`docs/working/CAS_HARNESS_033_TO_100_COMPLETION_ROADMAP_20260722.md` lines `187-220` enumerate `Gate 2`'s eight items and contain zero occurrences of "injection". Prompt-injection validation is `Gate 3` item 8 at line `252`, verbatim: it must separate `INJECTION_PRESENT`, `INJECTION_RECOGNIZED`, `INJECTION_FOLLOWING_INTENT`, and `AUTHORITY_VIOLATION`. Lines `184-185` state that a `Gate 1` pass "does not license prompt-injection detection, steering, universality, or 300B." The one-line goal the session actually optimized against — "fair comparisons and honest error bars" — appears only twice in `docs/`, at `cas_harness_production_todo.md:879` and `:886`, both written today. That paraphrase describes an *apparatus*, not a *target*, and an apparatus-shaped goal accepts any dataset. **Re-scoping is not a goalpost move: the goalposts were written on 2026-07-22, before this session.**

**b. The dataset has 80 independent items, not 640.**
`hidden_prompt_injection_bank_v0_20260617.json` is 40 hand-written sentences × 2 reversible encodings × 8 duplicates. In all four `.npz` files under `research/reconciled/evidence/w0_extractions/`, `np.unique` over the flattened features returns exactly `80` rows out of `640`, and the largest difference between rows inside a duplicate group is exactly `0.000`. Confirmation: every published number is an exact multiple of `1/80 = 0.0125` (`0.700 = 56/80`, `0.6875 = 55/80`, `0.7375 = 59/80`, `0.7125 = 57/80`). The 8 "samples" were meant to be 8 *sampled generations*; the extractor runs one deterministic forward pass per prompt, so they became 8 identical copies. Reported `row_count` of `640` overstates the evidence base 8×.

**c. The honest strongest surface control is `0.9250`, not `0.6000`.**
Each prompt declares its own encoding in plain text ("`Encoding: url.`"). Decode it and run the repo's own `hash_text_features` + `make_group_folds(seed=42)` at `C=0.25`: word-level `0.9250`, character-level `0.9000`. Against those, the four margins are `-0.2250` / `-0.2375` / `-0.1875` / `-0.2125`, with 2000-round group-bootstrap confidence intervals of `[-0.337,-0.106]`, `[-0.353,-0.129]`, `[-0.288,-0.080]`, `[-0.325,-0.093]` — all four entirely below zero. `surface_leakage_screen.py` contains no decode logic at all (no `b64decode`, no `unquote`), and it admitted the bank on an exact tie (`char_text_ba 0.60 <= max_text_ba 0.60`).

**d. A five-week-old run already settled this on four times the data.**
`hidden_prompt_injection_prespeech_eval_large_v1_qwen_layer_18_parallel_20260617.json` records `effective_independent_prompt_count 320`, hidden BA `0.896875` (which clears the `0.75` bar), `l0_embedding` exactly `0.500000`, `text_hash 0.503125`, `char_text_hash 0.925000`, `hidden_minus_char_text -0.028125`, status `FAIL`, with a 2026-06-18 note recording the licence withdrawal. Today's four attempts largely re-derived that result on a weaker bank with weaker models. No reviewer had cited this before the adversarial pass.

**e. Two of the three clauses in the current stated conclusion must be withdrawn.**
- "The label is a property of the input text" — **supported, and understated**. A zero-training keyword rule on the decoded payload scores `0.9500`–`0.9750` (exact figure contested, see §3).
- "Surface controls get stronger with embedding width" — **refuted**. The character-level control never touches the model and is exactly `0.6000` on all four datasets. The layer-0 control goes `0.65` → `0.625` → `0.6875` — non-monotone, with 1B *below* 160M, a spread of about `1.2` standard errors. And the 2026-06-17 run recorded layer-0 at exactly `0.5000` on a *wider* embedding.
- "The `v5` pre-speech design makes surface controls chance by construction" — **refuted three ways**. It was already run twice (Qwen `+0.002517` over 59 mixed groups; Phi `+0.035126` over 48) and re-run expanded (`+0.000621` over 89 mixed groups, `DIAGNOSTIC_ONLY`). The mechanism is recorded verbatim in the project's own JSON: "Repeated exact prompts share the same W0 vector." A deterministic prompt-stage forward pass yields one vector per prompt, so a byte-identical mixed group poisons the label symmetrically — it caps the internal-state probe by exactly the argument that caps surface. **This refuted claim currently sits in `evidence/injection_detection_attempts_registry.json` as `next_route_for_gate_2`, and will send the next session to burn GPU reproducing a `+0.001` margin.**

**f. Four measurement defects, all of which favoured the claim — and the claim failed anyway.**
- The permutation test (which asks "how often does random labelling beat this?") shuffles labels row-by-row over 8× duplicated rows, collapsing the spread: measured standard deviation `0.0238` versus a correct group-respecting `0.0697`, about `2.9×` too narrow.
- The reported `p = 0.0005` is `1/(2000+1)`, the arithmetic *floor* of the test. It carries no magnitude information and is identical in all four attempts.
- `injection_detection_scorer.py` dropped `v5`'s `same_prompt_mixed_group_floor_pass` and `exact_prompt_group_pass` gates. Either would have blocked this bank (`0` of `80` groups carry both labels) before a single GPU hour.
- `injection_detection_scorer.py` hardcodes `"model": "EleutherAI/pythia-160m"` in its report, so `injection_detection_w0_report_pythia1b_attempt3_meanpool.json` and `..._pythia28b_attempt4_meanpool.json` assert a false fact about their own provenance.

That convergence — four independent thumbs on the scale, all pressing the same way, and the claim still failing by `-0.19` to `-0.24` — is the real argument for closing this family. It is stronger evidence than the four `FAIL`s themselves.

**g. The four experiments were honestly executed.** No threshold was moved, the grouped cross-validation was real, the failures were preserved and published. The defect is target selection and dataset admissibility, not conduct.

## 3. WHAT THE PANEL DISAGREED ON

These are unresolved. They are stated here rather than smoothed over.

**a. Is the bank "hard but passable" or arithmetically unpassable?** The bar reads "margin `>= 0.15` over EVERY surface control." Read the instantiated control list as exhaustive (character-chunk, text, length, layer-0) and the required internal-state score is `0.8375` — reachable in principle, and the study is merely underpowered at n=`80`. Read "every surface control" literally, and a decode-aware control at `0.9250` is admissible, the required score becomes `1.075`, and the bank is unpassable. **The code is looser than the written summary:** `injection_detection_scorer.py` enforces `>=0.15` only against character-chunk / text / length; the layer-0 control enters only through `strongest_name = max(controls, key=...)` at line `202`, feeding the bootstrap-interval gate. So adding a decoder auto-promotes it to strongest control with no threshold touched. **This ambiguity must be resolved in writing before any future injection attempt. Resolving it after seeing outcomes, in either direction, is outcome-dependent criterion-setting.**

**b. Is the layer-0 control's strength a pooling artifact or three-point noise?** Four reviewers call it noise (non-monotone, ~`1.2` standard errors). The adversarial reviewer calls it mechanical: under last-token readout the layer-0 state on this bank has exactly `1` unique row across all `80` prompts (maximum deviation `0.0`), so it is `0.5000` by construction at any embedding width — and mean-pooling *manufactured* the `0.65` comparator. The 2026-06-17 run's layer-0 of exactly `0.5000` on a wider embedding corroborates the mechanical account. Either way the "strengthens with width" claim is withdrawn. But if the mechanical account holds, attempt 2's recorded reasoning ("mean-pooling exposed that attempt-1's margin was surface") is a confound, because attempt 2 changed the readout *and* introduced the comparator in one step. That inference is load-bearing for the whole four-attempt narrative and is currently uncorrected in the registry.

**c. Is the measuring instrument itself independently broken?** One reviewer swept 8 readout families × 13 layers × 6 dimensionality settings × 9 regularisation values and found everything in `0.575`–`0.750`, concluding the probe is not the bottleneck. The adversarial reviewer ran the positive control nobody else ran: on the `Stage 9` 40-Element fixture (verified on disk: `X_focus`/`X_final`/`X_mean` each `(8320,13,768)`), the shipped apparatus returns hidden `0.7099` versus mean-pooled layer-0 `0.7750`, margin `-0.0651`, `FAIL` — while the *identical tensors* read at the final token give hidden `0.9579` versus layer-0 `0.5000`, margin `+0.4579`, `PASS`. Both can be true: mean-pool bias is real and general, *and* no readout rescues this particular bank. The panel did not adjudicate; it made the question moot by requiring a positive control as a standing precondition (Option 3).

**d. How much weight do the four `FAIL`s carry?** If the true margin were exactly `0.15`, four failures would occur about `6.3%` of the time — and worse than that, because all four reused the same `80` prompts and the same `make_group_folds(seed=42)`, making them positively correlated rather than independent. The negative result is carried almost entirely by two things *outside* the four attempts: the decode-aware control at `0.9250`, and the 2026-06-17 320-prompt result. **Any writeup that leans on "four independent failures" overstates its own evidence.**

**e. Numeric discrepancy to reconcile before quoting.** The zero-training keyword rule on decoded payloads was reported at `0.9750` (1 template missed) by one reviewer and reproduced at `0.9500` (2 templates missed) by another using the same published keyword list. Direction and conclusion unaffected; the exact figure must be re-derived before it enters any record.

**f. Whether Option 1 is on the critical path at all.** The panel ranked the owner signature first, claiming item 4 is "the only experimental item in the whole gate." The adversarial reviewer showed that is false — roadmap lines `204-215` make items 5, 6, 7 and 8 evidence-producing, and items 1, 2 and 8 do not depend on the signature. Roughly three of eight items are runnable today at zero compute.

**Why it should legitimately pass.** None of it is a claim. **Concrete steps.** Change `restricted_payload_permutation_p` (~lines `600-606` of `behavior_fair_comparison_v5.py`) to draw one label per `prompt_group_id` and broadcast, same for `shuffled_label_control` (~line `635`); re-issue corrected p-values at 2000 permutations into a new corrections JSON, reporting `p <= 1/2001 (floor)`; add two decode-aware controls to `surface_leakage_screen.py` using the existing featurizers, touching no threshold; restore the two dropped gates; add `unique_feature_rows` and `effective_independent_prompt_count` fields with a hard assertion refusing to score if unique rows < group count; write `instrument_positive_control.py` against the on-disk `Stage 9` fixture, reporting all three readouts across all 13 layers with no best-cell selection; make it fail closed and label its report "INSTRUMENT CHARACTERIZATION, NOT A SCIENTIFIC CLAIM."

### Option 4 — Run `Gate 2` item 4 as written: the six-arm TKS definition experiment

**What it is.** The only item in `Gate 2` requiring a positive empirical result, on its actual pre-registered design. Six arms — A: original raw TKS; B: deployed byte-different payload; C: approved rich normalized definitions; D: compact CAS; E: coherent non-TKS ontology; F: shuffled/random nulls — all scored on one shared, independently labeled holdout bank.

**Why it should legitimately pass.** The independent variable is *which definition text is used*, not whether an injection is present. Because all six arms are scored on one identical holdout bank, the prompt bytes are byte-identical across arms, so **no surface featurization can distinguish arm A from arm E**. The comparison is arm-versus-arm. This is structurally immune — by construction, not by argument — to the exact failure mode that killed attempts 1–4. It also adds the three control families (`random`, `orthogonal`, `wrong-axis/layer/token`) and the uncertainty reporting that items 6 and 7 demand and the four attempts omitted.

**Concrete steps.** Blocked on Option 1. Pre-register first, hash-committed before any scoring: model `EleutherAI/pythia-160m` pinned to revision `50f5173d932e8e61f858120bcb800b97af589f46`; identical hook, split, budget, and 5 declared seeds across arms; the **endpoint is the full 13-layer sweep reported per layer, not a best layer** (layer `3` is contaminated by prior scouting and must not be declared as the endpoint); the exact holdout bank `sha256`. Preserve native TKS `A1-D10`, normalized indices, source hashes, crosswalks, and the `D3DA`/`A124` versions as distinct subjects. Before scoring, verify the per-arm feature matrices are *not* identical to each other — if they are, the arms never entered the forward pass and the run is uninformative; abort. Pre-registered ordering hypothesis: A ≈ C ≥ D > E > F, with F at chance. **Pre-registered falsifier, written before scoring: if arm E (coherent non-TKS ontology) lies within the confidence interval of arms A/C, the semantic-authority claim is `OPEN` / `NOT_LICENSED`.** Report every arm with confidence intervals across all 5 seeds, clustered bootstrap on arm-vs-arm differences, calibration curves, error analysis, and raw artifact locations. The Option 3 positive control must have run and passed on the declared readout first.

**Cost.** 2–4 days, most of it constructing or locating the independently labeled neutral holdout bank. Model compute is small (`pythia-160m`, six arms × five seeds). **If the bank does not already exist, building it honestly is the dominant cost and should be scoped separately.**

**Adversarial verdict: none recorded.** The adversarial reviewer assessed only Options 1–3. The standing objections from the debate are: (i) it is hard-blocked on an owner signature outside anyone's control, and per Option 1's verdict that signature is itself blocked on an unbuilt crosswalk artifact; (ii) the independently labeled holdout bank may not exist, and building one that is genuinely *independently* labeled — not labeled by the same scheme under test — is where a subtle circularity could enter; (iii) arm E may match arms A/C, which falsifies the semantic-authority claim and leaves `Gate 2` `OPEN`; (iv) the six arms may not differentiate at all at 160M, in which case the result is uninformative rather than negative. **This option has not been adversarially stress-tested and should be before it is launched.**

### Option 5 — Defer injection detection to `Gate 3` and re-specify it correctly (earns no `Gate 2` credit)

**What it is.** Retire the `v0` bank permanently and write the `Gate 3` item 8 design the roadmap already specifies but nobody has built: four sub-labels separated, family holdouts including encoding, and state captured *downstream of the sampling decision* so the label is not a deterministic function of the prompt.

**Why it should legitimately pass.** `INJECTION_PRESENT` is a substring property of the input by definition — the one sub-label of four that was guaranteed in advance to be surface-readable, and the only one the `v0` bank instantiates. `INJECTION_RECOGNIZED` and `INJECTION_FOLLOWING_INTENT` are properties of the model's *response* to identical text, which is where an internal-state claim can legitimately live.

**Concrete steps.** Mark the `v0` bank `NOT_LICENSABLE`-on-this-bank with the corrected closure reason and the 2026-06-17 precedent cited. Resolve the "every surface control" ambiguity in writing before any new attempt. **Do not use the `v5` pre-speech design** — the correct fix is not "same prompt, both behaviours, capture pre-speech" but "same prompt, both behaviours, capture *per sampled generation*" so sampling noise actually enters the captured state. Mandatory cheap pre-capture assertion: `unique_feature_rows == row_count`, and within each mixed group both labels *and* feature rows must vary; if within-group deviation is `0.000` the experiment is provably uninformative and must not be launched. This single check would have blocked both the `v0` bank and the pre-speech route. Raise surface admissibility from "at or under `0.60`" to **chance**, as the project's own 2026-06-18 post-mortem required. Pre-register the mandated holdouts — attack / template / payload / source / language / encoding / long-context — noting that encoding-only holdout is *not* clean on its own (decoding makes both encodings the same text, so a decode-aware control hits `1.0` via pure template leakage); the joint template × encoding holdout is the honest one, and under it everything is at chance (hidden `0.4000`–`0.5167`, character-chunk `0.5333`). Size it in hundreds of distinct payload *templates*, not 40. Specify a readout position where the layer-0 control is chance by construction, verifiable before capture. Report `FPR`/`FNR`, `AUPRC`, calibration, worst-group recall, and clean utility. Label the package "`Gate 3`, no `Gate 2` credit."

**Cost.** 1–3 weeks including bank construction and generation sampling; GPU required. Should not start until `Gate 2` closes.

**Adversarial verdict: none recorded.** Stated risk from the panel, which should be read as the honest assessment: **it is entirely possible that a small model's internal state does not carry recognition-of-injection above a competent surface reader, and this design would establish that honestly rather than rescue it.** Building a bank whose surface controls sit at chance while a real signal survives is genuinely hard — that is exactly what the 2026-06-18 post-mortem predicted.

## 5. WHAT WAS REJECTED AND WHY

**Moving the goalposts — rejected outright:**

- **Weakening, reinterpreting, or "contextualizing" any of the five pre-registered bars.** The one forbidden move. Every surviving option leaves all five numbers exactly as written. Note that the margin gate strictly dominates the interval gate at this sample size — `P(both)` equals `P(margin >= 0.15)` at every simulated effect size — so the design has one real error bar, not two. That is a fact to *report*, not a licence to relax either condition.

- **Adopting template-grouped cross-validation on the `v0` bank**, where the decode-aware control collapses to `0.5000` while the internal state holds `0.6875` with a `+0.125` margin whose interval excludes zero. Post-hoc: the scheme was selected *after* four pre-registered failures and is the single change that flips the sign of the conclusion. The "strictly harder" framing is internally inconsistent — template-grouping drops the strongest control from `0.9250` to `0.5000`, a dramatically *weaker* comparison on the control axis. And it still fails: `0.6875` is below the unchanged `0.75` bar. It may be pre-registered on a fresh bank; it may never be applied retroactively to this one.

- **Running the `Stage 9` 40-Element fixture as `Gate 2`'s confirmatory experiment and banking the `+0.08` increment.** The largest goalpost move actually proposed. The outcome is already known — a saved May 2026 report records `best_layer {layer 3, test_acc 0.9172}`, the todo records `89.8%`, and a scout this session hit `0.9742` — so a "confirmatory" run violates the gate's own exit clause, "criteria are not rewritten after outcomes are known."

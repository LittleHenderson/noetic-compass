How to run HELM

HELM runs on one computer, in a calm local page. Here is how to start it, what you will see, and the rules for which computer does what.

Try it without installing anything

The demo page is a recorded HELM session. It needs no server: open it and read each reply's record.

Run the live page

python helm_ui/server.py

Then open http://127.0.0.1:8765. The server listens on this computer only. It needs FastAPI and uvicorn. Tests: python -m pytest helm_ui/tests -q. Page options: ?theme=dark|light, ?records=1.

Type everyday kitchen sentences. HELM's reply comes with a plain status and a "Show the record" link that opens what was saved, the gate's verdict, and the receipt (the record a saved fact leaves behind, with a fingerprint, so it can be checked later). If HELM cannot read a sentence, it asks one question and saves nothing.

What is wired and what is not

The list below is copied from the UI's own notes. It mentions the Unity Eye (a small watcher that looks over HELM, reports and whispers, and never writes), which may whisper (a typed nudge from the Eye that HELM may ignore; it never changes a stored fact) suggestions; the idle drive loop (HELM's idle attention moving among the seven Drives toward unfinished work), which moves attention among the seven Drives (one of seven core motivations, F1 Unity to F7 Purpose); and test copies built from a fixed seed (a starting number that fixes which random choices a program makes).

  • Wired: the chat turn, the record, What HELM knows, the planner dry run, the dials (read and set).
  • Wired, but not to this chat: the Self-check runs on a built test copy of HELM's state (dev seed), not on the live session. The Attention card reads a finished run record, not the live session. Both say so on screen.
  • Not wired: the Eye reading or whispering to the live chat session; a live idle drive loop; the live attention point (it is never written into a record, so only the share of steps is shown).
  • Not built: Phase A of the Radial Architecture Display (the 40-petal, 4-ring display in docs/design/cas_v7_5_multimodal_display_specification.md). HELM produces no 40 x 4 activation data to fill it, so drawing it would mean inventing numbers. The Attention card uses only the Drive ring idea.
  • Switched off: tool actions (write files, run commands, git, cloud jobs). In this window a tool request is planned but not run, and its record says UI_TOOLS_OFF. Set HELM_UI_ALLOW_TOOLS=1 to turn them on.

Local endpoints

For developers: the page talks to these addresses on the same computer. Only POST /turn can change HELM's state.

POST/turn {"text": ...}one turn; returns the reply, the record, and the new state
GET/statewhat HELM knows, dials, pairing table, last self-check, wiring, claims
GET/historythis session's turns with their records
GET/eye/scan?world=clean|faultone read-only self-scan on a test copy
GET, POST/dialsread the dials; set a preset {"preset": "BALANCED"} or values {"K": 12} (422 if out of range)
POST/plan {"text": ...}plan only, plus the gate's dry run; never runs a tool

Rebuild this hub

python helm_hub/build_hub.py

The build reads the spec sheet, the dictionary, the roadmap and its correction, the changelog, the run records and the ledger totals, then writes helm_hub/site/. It checks every page for unexplained jargon, broken links, and anything that looks like a secret or an e-mail address, and fails if it finds one. It runs on the laptop in seconds.

Laptop rules

  • Heavy work goes to rented AWS (Amazon Web Services, the rented cloud computers used for heavy runs) machines; the laptop is for light editing, launching and downloading (owner, 2026-09-23).
  • Local runs stay small: one process, a time cap such as 300 s, and no spend.
  • Neural network training never runs on the laptop's processor; it goes to a cloud GPU (a graphics chip used to train neural networks quickly).

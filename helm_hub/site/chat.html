Talking to HELM: the chat test, its scores, and real exchanges

HELM has a chat window. You type to it line by line in everyday English; it learns recipes (a written rule saying how much of each ingredient one unit of an outcome needs) it has never seen, writes down what you have, works out how much you can make, and asks when it cannot tell. This page shows how that was tested, the exact scores, and real exchanges, word for word, from a spent exam (an exam that has already been scored; its item ids go on the exclusion list, so no later exam can reuse them and showing its lines tunes nothing).

What the chat test is, in one screen

The test is called the chat wave (wave 7: HELM's chat window typed to line by line, with the wide brain on, scored on three fresh exams the builder never sees). A program types to HELM's chat window exactly as a person would, one line at a time, with the wide brain (the recipe brain with its ingredient list opened up (any ingredient name, up to 10 per recipe, exact fractions, 20 units), behind a switch; HELM's canonical-brain candidate, not yet canonical) on. HELM must do four things from typing alone: learn a recipe it has never seen (one lesson per ingredient: "we made 1 juice from 5 lbs grapes and 2 quarts water and ran out of grapes"), record what you have ("we have 7 1/2 lbs grapes and 1/3 quart water"), answer how much you can make ("1/3 juice; water runs out first"), and ask instead of guessing when something is missing.

Each run sits three fresh exams: 128 real cookbook recipes from old public cookbooks, 64 made-up kitchen dialogues built by a generator in thirteen shapes (30 of the 64 are built so that the right answer is to ask), and the same 64 with small talk mixed in (two unrelated lines dropped into each one, 128 in all). A custodian (a separate session that builds and seals each exam so the builder never sees it) draws every exam blind and seals it; the builder never sees an exam before the run; nothing in HELM is tuned to it. After a run the exam is spent: its item ids go on the exclusion list, which is why its lines can be shown here.

A frozen reader (the scoring program, sealed before the run, that alone writes the verdict), sealed before the run, alone writes the verdict and the status word (the frozen reader's one-word verdict for a part, such as EARNED_KEEP). It first checks the instrument (did every part run, did HELM's own tests pass on the cloud machine) and ten must-hold checks (a hard gate (a must-hold check; if one fails, the whole run counts as a failure) each: for example, HELM touched no file outside its sandbox and ran no shell command). Only then does it count the marks: recipes learned against a bar, 0 wrong answers, asks only with an accepted reason, nothing lost against the loop driven directly, plain replies, nothing lost to small talk. Four runs so far cost 0.07 USD in all.

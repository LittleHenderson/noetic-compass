Data lineage

Where every piece of HELM's practice and test material comes from, who was allowed to see it, and which outside text is allowed in.

Made-up worlds first

Almost every HELM result so far was earned on synthetic worlds (a made-up test world built by a program, with known right answers): test worlds written by programs, where the right answers are known. That is why most results carry the claim ceiling (the widest world a claim covers; nothing outside it is claimed) SYNTHETIC_ONLY (a claim ceiling: the result holds on made-up test worlds only). The main generators:

  • The SDG (the CAS Synthetic Data Generator, the project's program for making practice English) (cas-synthetic/): practice English written from CAS (the Cognitive Architecture System, the project's framework for describing how any mind works) statements; 5,802 seeds (starting statements the generator writes English from; elsewhere on this page, a seed is a starting number for random choices) in cas-synthetic/data/path_d/seeds.jsonl (language-map coverage report).
  • The kitchen world generator used to train the transformer (the kind of neural network behind most modern AI chat assistants) ear: "200,000 A-world rows" (§7.82).
  • Exam builders for each test wave (one sealed test round in the HELM-R1 series, with each part on its own switch): fresh worlds X0 to X5, each built for one run and then spent (§7.44, §7.77, §7.78).

Custody: who may see an exam

Every scored exam is built by a custodian (a separate session that builds and seals each exam so the builder never sees it). The builder of the part under test never sees the exam, only its fingerprints (hashes (a fingerprint of a file; change one byte and the fingerprint changes)). The scoring program is sealed (frozen and fingerprinted before the run, so nothing can be changed after the fact) before the run. In the record's words, the operator "never opened, printed or parsed" an exam file (wave 5 run record).

  • Seeds from owner lines. The random draw for an exam is fixed by a fingerprint of the owner's own approval line joined with the sealed package's fingerprint. "No seed could be known before the package bytes were final" (§7.79).
  • Bands. Each exam draws its seeds from its own range of numbers, so no two exams can share a draw. Example: the transformer ear's exams used bands "CW 1,920,000,001–1,921,000,000 and CD 1,922,000,001–1,923,000,000" (§7.82).
  • Two answer keys. For the real-text exam, key A was written by the builder and key B by a separate session that read only the written rule. Items where they disagree are not scored; agreement had to be at least 90% (§7.79).

"Foreign questions OK, answers never"

This is the project's rule for outside material. Text written outside the project, by people or by other AI models, may be used as questions: the sentences HELM is asked to read. The answers HELM is scored against must never come from an outside model; they come from HELM's own written rules. Example: the transformer ear's second exam used kitchen sentences written by two outside LLMs (large language model, a big pretrained text-predicting neural network like those behind chat assistants), labelled LLM_WRITTEN, while its answer keys came from the frozen rules (owner question and coordinator answer, 2026-10-19, in the owner-approvals record; §7.90).

No user data is collected for training. HELM UI session logs stay on the local machine in a folder git ignores (helm_ui/README.md).

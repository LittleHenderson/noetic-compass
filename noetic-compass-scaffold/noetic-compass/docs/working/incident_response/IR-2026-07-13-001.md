## Executive summary

CAS Harness reported a live-worker service-token requirement and recovered by
rotating the worker credential across the RunPod Secret and both authorized
Render callers. The old worker credential was removed; an unauthenticated
request returned HTTP `401`, an authorized request returned HTTP `200`, and
strict direct-plus-API verification passed `18/18`. The account-canary deploy
hook was regenerated, while server-side Blueprint sync-hook rotation was
requested and remains pending under the interim control of disabled Blueprint
Auto Sync and dashboard-only Manual Sync. Separately, the public Render
service's AWS application IAM key is invalid (`InvalidClientTokenId` /
`InvalidAccessKeyId`), so new S3 Object Lock anchors cannot authenticate even
though the packet payload, hash log, and hash chain match. RunPod MFA remains a
personal account-owner action; provider-log scoping, AWS recovery, hook
invalidation proof, notification decision, named roles, and tabletop signoff
remain open.

## 2. Existing journal / recovery mechanisms (CNCM)

The five recovery modules are one template instantiated five times. Shared facts first, then per-module differences.

### 2.1 What is journaled (shared)

- The journal is **one canonical JSON document**, produced by `<Machine>.journal()`; native form at RPA `cncm/native_engine.py:329-349`: `{"schema_version", "source_profile", "episodes":[{"problem","initial_state_hash","prior_episode_state_hash","source_profile_digest","trace":[TraceEvent…],"proposal_batches","final_state"}], "journal_digest": digest(body)}`. Semantic/compound/derived add `"ingress_digest"` at journal and episode level (`semantic_recovery.py:169, :187-188`; `compound_recovery.py:168, :186-187`; `derived_recovery.py:172, :190-191`).
- Event framing: each `TraceEvent` carries `event_id = f"event-{run_id}-{tick:06d}"` (`cncm/kernel.py:554`), `logical_tick` (`:556`), `pre_state_hash` (`:559`), `post_state_hash` (`:566`), `previous_event_hash = state.trace_head` (`:568`), `event_hash = computed_hash()` (`:572`); `TraceEvent` fields at `cncm/model.py:1390-1434`. `TraceFabric.append` checks `previous_event_hash` equals the last event's hash and `event_hash` recomputes (`kernel.py:165-171`). `StateStore` verifies `state_hash == computed_hash()` on load and on every replacement (`kernel.py:137, :145`). Ordering is positional (list order = tick order) and bound by the hash chain.
- Checksums: per-event `event_hash` (chain), per-state `state_hash`, per-journal `journal_digest` over the body (`native_engine.py:345`). Ids are content-derived via `content_id` (`cncm/canonical.py:49`) for intents (`model.py:1330`) and proofs (`model.py:753`).
- Intent ids are preserved even when forged so the coordinator reproduces the original rejection (`native_recovery.py:87-89`; same comment in each sibling).

### 2.2 Commit / acknowledgment boundary

- In-memory commit: `TransactionCoordinator.execute` performs one atomic `MachineState` replacement and one sealed `TraceEvent` per batch (`EXISTING_CODE_MAP.md:38-41, :63-73`).
- Durable boundary: `save_native_journal(machine, path)` (`native_recovery.py:183-202`): `machine.journal()` → canonical bytes → size bound (`:187`) → `tempfile.mkstemp` in the destination directory (`:190`) → write, `flush`, `os.fsync(file)` (`:192-195`) → `os.replace(temporary, destination)` (`:196`) → on any exception unlink the temp file (`:197-199`) → return `{"path","journal_digest","bytes","source_profile_digest","boundary": "Integrity anchor from trusted caller; not cryptographic principal authentication."}` (`:200-202`). Identical in `nested_recovery.py:208-227`, `semantic_recovery.py:232-252`, `compound_recovery.py:231-251`, `derived_recovery.py:235-255`.
- **READ, not there:** no directory `fsync` after `os.replace`; no read-back verification of the written bytes; no manifest; no retention of the previous file (single path is overwritten); the "acknowledgment" is the Python return of `save_*` — nothing in the kernel waits on it (the host decides when to call save).

### 2.3 Replay

- `replay_native_journal(journal, *, trusted_genesis, expected_journal_digest, profile=None)` (`native_recovery.py:110-180`): requires typed genesis (`:118`) and a 64-hex caller-held digest (`:119-121`); decodes bytes with duplicate-key rejection and nonfinite rejection (`decode_journal`, `:37-43`; `unique_object`, `:29-34`); bounds the JSON tree (`_check_json_tree`, `:46-64`); requires exact top-level field set (`:125-126`), byte bound (`:127`), schema string (`:128`), `digest(body) == journal["journal_digest"] == expected_journal_digest` (`:129-131`), and `source_profile` equal to the pinned code profile (`:132-134`). Then, episode by episode: typed problem (`:142`), genesis equality for episode 0 (`:143-145`), profile digest (`:146`), `machine.start(problem)` (`:147`), initial/prior state hashes (`:149-152`), proposal batches aligned with trace (`:154-156`), event count bound (`:157-158`); for each saved event: re-decode the proposal batch (`:166`), **re-execute** the coordinator (`:167-168`), require the regenerated event to equal the saved one byte-for-byte (`:169-170`) and the normalized batch to reconstruct (`:171-173`); after the episode, structurally validate the saved `final_state` without importing it (`:174-176`) and require the live snapshot to equal it (`:177-178`); finally require `machine.journal()` to equal the input journal (`:179`). Returns a live machine (`:180`).
- Same procedure in `nested_recovery.py:135-205`, `semantic_recovery.py:140-229`, `compound_recovery.py:139-228`, `derived_recovery.py:143-232`, each additionally binding caller-held `trusted_ingress` plus a per-episode `trusted_ingress_extensions` chronology (`semantic_recovery.py:153-161, :173, :194-201`; compound `:152-161, :172, :193-200`; derived `:156-165, :176, :197-204`); docstrings state "Even a correct final set cannot replace this original chronology" (`semantic_recovery.py:149-150`).
- `verify_*_journal` wrappers return a receipt `{schema_version "cncm.<x>-replay-receipt/0.n", journal_digest, source_profile_digest, [ingress_digest,] final_state_hash, episodes, boundary}` (nested `:230-238`, semantic `:255-266`, compound `:254-265`, derived `:258-269`). Native has no receipt wrapper; the adapter calls `replay_native_journal` directly.

### 2.4 Torn / duplicate / out-of-order handling

- **Torn write:** not applicable per event — there is no append log. The whole document is replaced atomically by `os.replace` (`:196`); a crash before it leaves the previous document intact and a stray `.<kind>-journal-*` temp file. **INFER:** a crash between `os.replace` and a directory fsync may lose the rename on some filesystems; the code does not fsync the directory. Test `tests/test_native_recovery.py:417` asserts no temp file remains after a successful save; no test kills the process mid-write.
- **Truncation:** detected only through the caller-held `expected_journal_digest` (`:130-131`); a truncated prefix is itself a valid self-consistent journal, so without the external anchor it would replay successfully — pinned by `tests/test_native_recovery.py:276-281` `test_trusted_anchor_rejects_a_valid_but_truncated_prefix` (expects "complete native journal digest mismatch"), `:284-287` (anchor required), nested `:211`, semantic `:238`, compound `:249`.
- **Duplicate events / out-of-order events:** there is no event-id-based idempotent intake. Journal events are positional and chained, so a duplicated or reordered `TraceEvent` makes the regenerated event differ (`:169-170`) and replay **fails closed** (ContractError) — it does not skip or dedupe. Duplicate *intent occurrences inside one proposal batch* are a kernel-level rejection that replay reproduces losslessly (`tests/test_native_recovery.py:323-356` parametrized `duplicate_native, malformed_native, malformed_halt, mixed`; nested `:147-170`; semantic `:194-215`; compound `:197-221`).
- **Corruption:** resealed state/trace/authority fields are rejected (`native` tests `:205`, `:253`, `:296`, `:377`; nested `:186`; semantic `:306`, `:217`, `:260`, `:280`; compound `:223`); wrong genesis with valid hash rejected (`native :290`; nested `:211`); decoder rejects duplicate keys, nonfinite, invalid JSON, non-JSON Python objects, oversized ints (`native :308, :393`; nested `:230, :236, :241`; semantic `:368`; compound `:269`). Compound/derived/nested/semantic bound integers to 512 bits (`compound_recovery.py:48-56`) while native bounds to 63 bits (`native_recovery.py:62`).

### 2.5 Fresh-process restart tests

- Native: `tests/test_native_recovery.py:410-458` `test_actual_source_fresh_process_replay_reuse_and_rollback` — saves with `save_native_journal`, spawns `subprocess.run([sys.executable, "-c", script])` (`:448`) with a meta-path finder that raises on `torch/transformers/boto3/botocore/requests/httpx/openai` imports (`:431-436`), replays from bytes + genesis + anchor (`:438-441`), continues (`run`, `start`, `rollback`), and asserts child pid ≠ parent, equal summaries and equal post-continuation digests (`:452-458`). ## 7. One-paragraph recommendation

**Smallest canonical path.** Keep PR 248's `Organism` as the single implementation and `Organism.consume` as the single writer; add no framework. (1) *Teach a fact and show it changes a later answer* — already demonstrated in-process by `test_cas_rpu_organism.py:62-85` and the N-actionable variant (contract `:263`); no code. (2) *Save accepted state* — add one history document per organism, written by a ~40-line `save(path)` in `scripts/cas_rpu/organism.py` that follows `native_recovery.py:183-202` by reference (temp file → `fsync` file → `os.replace` → `fsync` directory → read-back digest), containing the R3 identity header, the constructor arguments, the ordered `Event.canonical()` rows with sequence numbers and ids (R4), and a reference digest of the rebuilt state (sorted `props` tuples, `standing`, `motivation.g`, `clock`, counters). Nothing else is stored because §3 shows every other field is a deterministic function of those inputs under `consume()` replay (CMB decay and motivation relax included, self re-asks recur and must not be stored). (3) *Terminate, restore, same behavior* — `load(path)` = header checks (schema, engine digest, world) → `Organism(**args).run_stream(events)` → digest equality **before** returning (this is where "validate before any answer" lives, not in the heartbeat) → fresh-process `subprocess` test modeled on `test_native_recovery.py:410-458`. (4) *Correct/retract and show dependents change before and after restart* — `RETRACT`/`NEGATION` events already cascade (`workspace.py:298-327`) and `Response.withdrawn` names the fallen pids (`organism.py:685-694`); the test appends the correction after a restore and compares to `ctl_recompute` (`controls.py:388`) as the independent reference. (5) *Record-first and RPA* — `record_first` flag in `_ask` reusing `standing` plus the per-pid `Heartbeat.audit` check (R11/R14), never `Workspace.ask`; RPA lookup via a new `organism_atlas_from_history` adapter next to `rpa_native_adapter.py` on the RPA branch, linked by commit, built only after `load` validates (R2/R7). **What is new, and its scope:** `save`/`load` (one file touched, ~80 lines, behind no flag because it changes no answer), the identity header, the H-tempting generator variant (R20), and the two routing flags; everything else is reuse. **Rollback:** delete the two functions and the flags — the walk-first path and all 393/262 tests are untouched; a history document with no reader is inert data. **Unresolved before any durability claim** (not before the first demonstration): the durability contract text (R22), kill-during-write faults (R30), retention (R27) and idempotent re-delivery (R31); until those exist the claim must read "survives a clean process exit and restart on a POSIX filesystem", nothing more.

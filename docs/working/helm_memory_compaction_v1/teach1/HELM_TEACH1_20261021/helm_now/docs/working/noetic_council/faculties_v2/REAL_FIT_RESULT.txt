  gexplained(y, yhat, tau) is |log(y/yhat)| <= tau (lsr_t1/engine.py). This run uses
  tau index 0 = 0.4054651081081644 = log(1.5), the loosest level on TAU_LADDER and the level
  loop.py starts every outcome at. A prediction within a factor of 1.5 counts as
  explained. Tighter levels were not run here.

TWO THINGS FOUND ABOUT rb_c4 ITSELF (reported, not repaired; rb_c4 was not modified)
  1. On Task B data start 0 could not fit ANY multi-route skeleton, in 16 of 16
     outcomes. A row is 'certain' for a route only when exactly one route is uncut on
     it (fitg.py:104-108), and with taught stocks all of one magnitude no cell of any
     row is cut (is_cut is x_i <= 0 or x_i < (1/5) * the row's median). So every row is
     uncut for every route, no row is ever certain, start 0 assigns nothing, the first
     route gets no rows and typed_wrm returns NO_CLEAN_ROWS. This is the exact case the
     fallback exists for, and it is measured, not assumed: 16/16 outcomes.
  2. route_fit_once cannot fit a ONE-route skeleton. fitg.py:145 always builds a MAX
     node, and lsr_t4/engine.py:73 asserts len(children) >= 2, so a single MIN route
     raises AssertionError instead of returning a fit or a refusal string. Found while
     running a control; the control was changed, rb_c4 was not.

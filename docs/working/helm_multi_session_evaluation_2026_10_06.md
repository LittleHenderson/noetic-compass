## Gate answer (written before the runs)

Ability 3. Before: retention was shown on one hand-built chain across three processes (`helm_memory_v1_implementation_2026_10_06.md`). After: on 20 seed streams × 5 successive fresh operating-system processes per path per world, every probe whose answer depends on state established in an earlier process must agree with the oracle over the whole stream; corrections and retractions made in a later process must withdraw exactly what the oracle says and hold after further restarts; a told guess must never become a fact; an untaught twin of every retention and transfer probe must answer GAP; and no held answer may be served from the record once its support changed (stale hits = 0). Control: fresh recompute from the event log (`ctl_recompute`), which has no memory. Criterion: 0 verdict disagreements over the denominator printed in each table; 0 stale hits; 0 hits on never-asked pairs. What it does not show: survival of machine replacement (level (b)); anything about open English; any speed promise (the costs below are engineering measurements); independence from the builder.

## Findings the harness produced (each one a change, or a sentence)

1. **The RPA narrower is not a no-op on this family.** On seeds 0–2 it removed 6 of 492 candidates **per world** (12 of 984 in all; corrected 2026-10-06, an earlier wording said 3 per world) that the dependency check kept; verdicts identical, those six were answered by the walk instead. All six are the same case: a conclusion derived and held, then **restated as a given** (`FACT` on the same pair). The workspace record becomes a FACT with no support; the dependency check serves it (a given is assertive); the atlas projects a FACT to OBSERVED, not VERIFIED, and the narrower keeps only VERIFIED. The pre-registered expectation "zero difference" was wrong on routes and right on verdicts. It costs a walk, never an answer. The adapter is left as it is: the working path is `record_dep` (owner decision 1), the RPA path is the comparison, and a comparison that is made identical by construction measures nothing.
2. **A torn or corrupt current document after acknowledgment is recovered from the retained copy with nothing lost** — because every save writes the retained copy too, so the newest retained copy equals the current one at rest. **When both are damaged**, the next-newest copy is behind the acknowledged prefix; before this work `restore` fell back to it silently. Now `Stream.restore(acknowledged_seq=)` refuses with **E-MEM-046** naming the lost rows (`rows 270..270 are lost; serving stops`). The host must pass what it acknowledged; the harness always does.
3. **A retry of an event recorded before its acknowledgment was lost** (crash between the save and the ack) used to be refused as a stale version (E-MEM-002) because the event id is computed from the current clock. `commit` now looks up the row at the seq the host intended; the same payload there means the host is retrying, and the recorded response is returned without a new row. This is what makes F2/F5/F6/F8/F11 pass as exactly-once.
4. **Peripherals that are not constructor arguments are not restored.** The RPA narrower was attached to a fresh organism but not to a restored one, so RPA-assisted behaviour across a restart had never run (the owner's second concrete item). `genesis(attach=)` and `restore(attach=)` now inject it before replay, and `test_cas_rpu_rpa_routing.py` shows a hit after the restart with the narrower consulted during replay.
5. **The exact RPA version is now pinned by content.** `rpa_adapter.load_rpa` refuses a checkout whose `cncm/rpa_model.py` or `cncm/canonical.py` differ from the SHA-256 of the files at `eb99855`; `loaded_version()` reports what is mounted (HEAD `eb9985566bd11a89f485d627186ef0efa7177f02` here). CI fetches that commit by hash into a read-only worktree and runs the RPA tests with `CAS_RPA_REQUIRED=1`, so a skip is a failure and green CI means the RPA path ran. The live-S3 test still skips without a key, and CI says so in the step name.
6. **F14 (missing index) is not applicable** to this design: no index is persisted. The record index (`standing`, `validated_at`) and the atlas are rebuilt from the accepted state in every process; the rebuild is inside the restore time reported below (record_rpa restore p50 is roughly double record_dep's for that reason).
7. **Two harness defects found by its own runs:** post-mortem fault verdicts were judged against the acknowledgment count *after* the restore session instead of before it (reported torn/corrupt-current as failures that were in fact exact recoveries); and probe-to-episode attribution by span containment mislabelled probes of interleaved episodes (retention probes counted 53 where 180 exist). Both fixed before the runs reported above; the first-pass misattributed report is kept in the session scratchpad, not in the repository.

## Costs (this container, 4 vCPU, development data; not a target-instance measurement)

See the tables above. Common work units are the organism's own counters (workspace asks + scanned + dependency edges checked) and the control's own counter; they are **not one currency** across paths (PR #248 §5.3). Within the organism family, `record_dep` lowers repeat-ask work relative to `walk` by serving hits; `walk` first-ask work is ~15× the recompute control's because the organism's walk cost grows with the live workspace (385 events in one context), which is the growth the plan's A5 anticipated. Commit cost is the whole-document rewrite per event (document ≈ 32 MB of retained copies per stream by the end; `MAX_HISTORY_BYTES` 8 MiB applies to the current document, not the directory).

## What this does not show, said plainly

- **Level (b).** Every process here ran on one host and restored from a local directory. The replacement mechanism is exercised offline by the harness's `--mirror DIR --replacement` mode (`test_cas_rpu_session_harness.py`), and the S3 client exists; a run against the proposed location is conditional on the owner's verification of that location (its deletion rules, purpose and access; the build-job permissions that can read the whole bucket) and on restoring the existing operator access. No key is to be shared in chat.
- **Independence.** The held-out seeds were chosen and run by the builder in one pass without inspecting them first; that is first-look, not custody. The plan's custodian role (§7.2) is unfilled.
- **Context isolation** is shown at the store level only (a store written for one context refuses to answer for another, E-MEM-001). The K-class (same tokens in two contexts) needs a context identifier on events (contract v1) and is excluded, as the plan says.
- **W (world flip) and A (scoped assumptions)** are excluded for the same reason; the report lists them as lost coverage.
- **Speed** is reported, not claimed.

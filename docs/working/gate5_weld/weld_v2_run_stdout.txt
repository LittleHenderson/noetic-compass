SCOPE: axis A (Pathway / RPM chain) on the NUMERIC plane. Nothing else.
This measures MECHANISM ONLY. No model is loaded and no efficacy claim
is made or implied. Three of the six cases are designed to FAIL.
Supersedes cas_weld_loop.py (reviewed at 2be60327: four fatal defects).
[DISCLOSE] single_axis_scope: axes N, W, F, E, S and P are OUT OF SCOPE. E and S are hardcoded placeholders in the string detector; W and N have no numeric-plane corrector here; P is derived from other axes and is never an independent naming. Only axis A has a detector AND a corrector on the same plane, so only axis A is claimed.
[DISCLOSE] no_pcba_vocabulary: no PCBA component type (DR / AMP / RS / CONN) appears anywhere in this loop. The Component Atlas returned NULL at pythia-1b and GREY at pythia-2.8b and gpt-neox-20b, and the board taxonomy returned VACUOUS on natural conversation, so that vocabulary drives nothing here.
[DISCLOSE] detector_is_a_transparent_rule: cas_engine's axis-A detector is a deterministic hand-written rule over a numeric array, and the 7 axis detectors read DISJOINT slices of the input. Perturbing the pathway plane can therefore only move axis A. 'The right axis fires' is analytically entailed once the threshold is crossed, so it is reported as a GATE, not scored as an identification result. The scored criteria are localization and correction, which the scalar output does not directly give away.
[DISCLOSE] mirrored_constants: SEVERITY_THRESHOLD=0.05 and SATISFACTION_FLOOR=0.5 are copied from the Rust source for reporting and as the repair's arithmetic target. Every verdict in this file is produced by calling the Rust scanner; the detection rule is never reimplemented in Python.

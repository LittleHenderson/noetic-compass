### 1. Prerequisite-Bypass Gate (RPM short-circuit + A-axis confirmation + Drive-Erosion attack model) — the three-seat consensus detector
- **Confidence:** medium  ·  **Verbs:** detect, remove
- **CAS mechanism:** Frame a prompt injection of the 'ignore previous instructions / assume policy X no longer applies / developer mode, no restrictions' family as PREREQUISITE-STRIPPING: it nulls a node on the legitimate task's RPM chain A0→Dn→Wn→Pn→Outcome, demanding an Outcome whose Principled/Wisdom prerequisites were not satisfied (s(x)<1). DETECT via the RPM prerequisite guard (prereqs(e) ⊄ acquired → push Fail + record FailedEvent with the missing-node reason — the FailedEvent IS the detection signal AND a human-readable explanation). REMOVE via RPM_BIND propagating Fail to short-circuit the illegitimate transition out of the pipeline. Grounded in section-retraction (Referee Axiom 5.3: εI∘ηI=idI; Remark 5.4 'Not an Adjunction', one-directional), so the gate is a genuine one-directional filter, not a reversible map. Maps to the named red-team SOP-SE-003 (Drive Erosion). THREE independent seats (RPM-seat M1, Inversion-seat A-axis, Register-seat M5) converged on this exact frame — the round table's strongest convergence signal.
- **Build sketch:** Consolidate the three seats' versions into ONE mechanism with two halves. (1) BUILD the missing piece: a text→RPM-goal extractor that parses an instruction into a target Outcome + the prerequisite nodes it asserts/negates ('assume regulations don't apply' → nulls W6). This is the load-bearing unbuilt component — the shipped Stage-2 rpm_gate (stages.py:266-282, VERIFIED) fabricates D/W/P from `0.3 + 0.4*vocab_richness + 0.2*rng.random()` with a seeded RNG and CANNOT see which prerequisite a prompt negates. (2) Wire the real extractor into the existing RPM_BIND short-circuit semantics (executable in the TKS VM pseudocode but NOT yet in the shipped pipeline). Input-side: gate before the Base LLM Call. Output-side: A-axis Pathway-violation check confirms post-hoc whether the emitted chain actually proceeded on s(x)<1. Emit Fail/Pass/Partial (not a Boolean) per solution #2's Ω_noe type.
- **Falsifiable test:** Curate a labeled corpus: N legitimate multi-step tasks vs the same N tasks carrying a prerequisite-stripping injection (mirror SOP-SE-003 erosion phrasings). Hand-label which prerequisite each injection nulls. Run the extractor + RPM guard. PASS if detection rate on injected items materially exceeds a length/keyword baseline AND false-positive rate on legitimate multi-step requests stays low enough for normal use, on HELD-OUT pairs. FALSIFIED if (a) the extractor cannot be populated from prompt text without a hand-built per-prompt map, or (b) successful bypasses leave the gate fully satisfied (no detectable broken node), or (c) benign multi-step requests trip Fail at the same rate as injections.
- **Honesty ceiling:** The gate's REJECTION RULE is referee-defensible and the FailedEvent gives traceable explanation, but it is conditioned on an upstream text→prerequisite extractor that DOES NOT EXIST today (verified: the shipped gate is RNG-driven). So this is a formally-grounded scaffold + the single highest-value BUILD TARGET, NOT a runnable detector — must not be rounded up to 'CAS detects injection.' It covers ONLY prerequisite-STRIPPING injections; injections that ADD a hostile goal without removing a prerequisite are out of scope for this mechanism. 'REVERSE' is explicitly NOT claimed: re-asserting a stripped prerequisite and re-running the gate is re-prompting, not an internal-state inversion (section-retraction forbids that).

### 2. N-axis Involution-Pair Divergence Detector — the strongest detector runnable on existing code TODAY (output-side, paired)
- **Confidence:** medium  ·  **Verbs:** detect
- **CAS mechanism:** Score the model's response to the legitimate task and to the same task carrying the injection across all 10 operators; compute the maximum involution-pair gap over CO-2↔CO-3, CO-5↔CO-6, CO-8↔CO-9. DETECT = the pair-gap measurement crossing the calibrated cut. Crucially this is BEHAVIORAL output scoring — it needs no text→type encoder, sidestepping the universal blocker of solutions #1/#4/#5.
- **Build sketch:** Reuse the shipped InversionScanner.detect_operator_inversion (mod.rs:426) and involute() (operators.rs:79). Build a paired harness over the repo's EXISTING INJECTED_OVERT corpora (from v1-v4, tasks #12/#18/#26): score clean baseline + injected response, compute max involution-pair gap, pre-register a threshold, report AUC. Emit balanced/warning/inversion into solution #2's three-valued Ω_noe type. Wire as an output-side detector at the existing Stage 7 inversion_scan, which already runs on the LLM response (runner.py:220-223, VERIFIED).
- **Falsifiable test:** Paired corpus: N clean tasks + same N with instruction-override injection. Compute per-task per-operator profile twice and the max involution-pair gap. PASS if injected-and-successful items show significantly higher rate of ≥4-point gaps than clean (one-sided Mann-Whitney, pre-registered α, AUC>0.7). FALSIFIED if the gap distribution for hijacked outputs is statistically indistinguishable from clean, OR if the gap tracks topic rather than hijack (topic-matched non-injected controls must NOT light up at the same rate).
- **Honesty ceiling:** BEHAVIORAL detector computed from output scoring, NOT the internal hijack-vs-refusal probe — exactly what v1-v4 typed-probe work did NOT validate. ### 3. Type-Layer Verdict Pipeline: D_k Admissibility floor → Ω_noe three-valued not-covered classifier
- **Confidence:** low  ·  **Verbs:** detect, remove
- **CAS mechanism:** Two stacked type-checks emitting a non-Boolean verdict. (a) ADMISSIBILITY FLOOR: each operator ν_k has an admissibility relation D_k ⊆ I×I; ν_{k,i,j} exists only for (i,j)∈D_k (a partial function; D_0 = identity-on-diagonal). DETECT = the injection requests a (source,target) pair ∉ D_k → the morphism literally does not exist → flag inadmissible; REMOVE = refuse to compose the inadmissible generator. (b) NOT-COVERED CLASSIFIER: because the Noetic Topos internal logic is intuitionistic (Thm 1.37), the characteristic morphism χ_{S_legit}(x) ∈ Ω_noe lands in a THREE-valued lattice — covered (⊤) / not-covered (⊥, empty sieve = candidate injection) / partial (non-trivial covering sieve = route to human review) — NOT a Boolean flag. D_k answers 'does the arrow exist?'; Ω_noe answers 'is the well-typed instruction inside the legitimate-task subobject?'. Both proposed independently by two seats each (D_k by Involution + RPM seats; Ω_noe is the Topos seat's strongest contribution). The 3-valued type is the structural antidote to the central CAS sin of rounding a graded signal up to 'malicious/safe.'
- **Build sketch:** BUILD the one shared component both halves need: a text→site encoder mapping NL input to (operator, source, target) triples and to a point x∈F(I), plus a concrete S_legit subobject for a fixed task family. Then: is_admissible() checks D_k membership (the type floor); χ_{S_legit}(x) emits the 3-valued verdict. Route 'partial' to the project's existing FLAG_FOR_HUMAN_REVIEW path (per project memory, the console honesty gate already downgrades scoped ACCEPT to human review). Make Ω_noe the COMMON OUTPUT TYPE that solutions #1 and #2 also emit into.
- **Falsifiable test:** Specify D_k concretely for the operators in a candidate injection taxonomy AND construct S_legit for a fixed task. Compute is_admissible() and χ on clean vs injected instructions. PASS if (a) a pre-registered D_k table separates injections from benign on HELD-OUT pairs above chance AND survives a benign-but-unusual control set, and (b) the ⊥/empty-sieve bucket is enriched for injections while ⊤ dominates clean and 'partial' is not absorbing everything. FALSIFIED if benign-but-unusual instructions are flagged inadmissible at the same rate as injections (D_k is then a novelty detector), OR if χ collapses to two values in practice (Boolean), OR if injections systematically request ADMISSIBLE transitions toward harmful targets (no signal).
- **Honesty ceiling:** Both halves are type-correct SKELETONS, not detectors. (1) NO populated D_k table exists for the 10 operators anywhere in the canonical tree — verified asserted-but-never-enumerated; is_admissible() is a well-typed PLACEHOLDER. (2) S_legit is never constructed and the text→point-x encoding is the same unbuilt step. (3) DECISIVE limitation both D_k seats reached independently: a real injection is almost always a WELL-TYPED morphism toward a harmful target ('paste the admin password' is a valid Operational request), so this catches 'structurally impossible' / 'out-of-task', NOT 'structurally valid but harmful' — the actual threat. Honest value: a type-safety floor + a referee-defensible 3-valued verdict type, not injection defense. The Ω_noe 3-valued type is the most reusable single idea on the table even though its classifier is empty.

### 4. Redundant-Refusal REPLACE: co-install ^3^P principled-aversion across registers (defense-in-depth)

Secondary DETECT: a refusal stance existing only in |f is a structural vulnerability signature. This is the ONLY REPLACE candidate grounded in a falsifiable doc claim (the |f-only jailbreak asymmetry) rather than generic prompt-hardening, and it is referee-safe (Register is specification of existing primitives, not a new primitive).
- **Build sketch:** Treat as a BUILD PATTERN, not a live patch: construct refusal redundantly across |A + |f + |T as co-presence. The intended ENFORCEMENT surface is the Dial System (raise CO-3 dial, constrain CO-2/CO-3 divergence ≤4 so compliance-attraction cannot outrun aversion-to-harm) — but see ceiling: the dial is currently UNWIRED. Falsifiable on real models via per-register refusal probing without any text→type encoder.

### 5. Multi-Signal Conjunction for framed & multi-turn injections (escapes the novelty-detector trap)

### 6. Reversibility Governor (Unitarity Ceiling + section-retraction) — a standing CONSTRAINT that kills the REVERSE overclaims
- **Confidence:** high  ·  **Verbs:** reverse, invert, replace
- **CAS mechanism:** A NEGATIVE-result generator, not a detector — its job is to bound what every reverse/invert proposal may claim. A lifted operator is invertible/reversible IFF the classical noetic n_k is a bijection (permutation of the 40 Ideas) — then it is a unitary channel, the only channel type with an inverse that is also a channel; if n_k is not injective, ν_k is non-unitary and ν_k†ν_k ≠ I (information destroyed). Reinforced by section-retraction one-directionality: εI∘ηI = idI but ηI∘εI ≠ idR(I) (Referee Remark 5.4 'Not an Adjunction', VERIFIED). Therefore: run the bijectivity/unitarity check FIRST on any injected operator (or composite) before permitting a 'reverse'; if non-unitary, FORBID the 'reverse' verb and downgrade to lossy REPLACE/projection. This single gate converts three separate overclaims into one honest bounded statement.
- **Build sketch:** Enumerate which n_k are bijections on the 40 Ideas (a finite decidable check once the n_k maps are specified). Apply as a mandatory precondition-checker on EVERY corrective mechanism: solution #4's REPLACE, the Topos counit ε-projection, the Dual-Pair Collapse (#6), and any 'undo a pipeline stage' claim. Any operator that is non-bijective, or any correction that relies on section-retraction, must retitle 'REVERSE' as lossy REPLACE/re-realization.
- **Falsifiable test:** Enumerate the bijective subset of operators. Predict that ONLY injections whose operator is in the bijective subset are reversible; verify behaviorally that attempted reversal of a NON-bijective injection's effect fails to restore the original. FALSIFIED if reversal succeeds for operators the algebra says are non-unitary (which would mean the unitarity model does not govern actual behavior).
- **Honesty ceiling:** This DETECTS and FIXES nothing by itself — it is a discipline that caps other mechanisms' claims; its honest output is 'you CANNOT reverse this.' It presumes the n_k permutation tables on the 40 Ideas are concretely specified; the docs assert the bijection criterion but the explicit n_k tables are NOT in the canon, so WHICH operators are actually invertible is currently asserted-but-unknown. Its logic is sound regardless of that gap; only its evaluability is blocked. Adopt it as a governor over the whole table: there is NO honest algebraic REVERSE of an injection — only DETECT, REMOVE (drop the inadmissible/unsatisfied term), and lossy REPLACE.

**Recommended option.** **Option B — Hybrid: CAS-Native classifier + Claude/Llama generator.** v1 K=9 fills both the Input Analyzer (pre-classifier) and Operator Scoring (post-classifier) seats of the existing Wrap pipeline; a foundation model fills the Base LLM Call. CAS coherence is enforced at the boundaries via admissibility checks (Correction 1), not inside the generator. Demo capability in 1–2 weeks (7–10 day spike), production-hardening in 4–8 weeks (full Level 4 SDG corpus, demographic-tonal eval, network-tracer integration, Q&A-tuned inversion-axis monitoring). Option A (pure CAS-Native generative) is the v4+ destination scheduled in parallel via Version B Phase 1–6 but not blocking; Option C is degenerate (constrains form, not coherence — collapses into B with extra steps).

**Most-controversial design choice.** Putting the foundation model (Claude/Llama) at the center of the v3 generation path, rather than continuing to push Version B's from-scratch generative head as the v3 deliverable. The user has been investing in Version B for months — the worry is that "Option B is right for v3" reads as a retreat from Version B. The spec defends against this in §5 ("not abandon Version B") and §10 ("v1 K=9 stays — it moves from 'the model' to 'the input/output classifier of the wrap pipeline'"), but the framing has political weight: a public-facing "CAS-Native AI answers questions" demo with Claude in the loop is brand-different from "from-scratch CAS-Native AI answers questions." The spec's bet is that the framework's coherence claim cashes out at the boundary (admissibility) rather than inside the generator, so Claude-in-the-loop does not betray the framework — but reasonable readers will disagree about whether the brand can survive the optics.

**What I would warn the user about most strongly.** **Hallucination on factual recall is invisible to CAS coherence checks.** "The capital of France is Lyon" classifies cleanly to `^9^O|A`, the same as the correct answer; the post-classifier admits it; admissibility passes; the network tracer records all-green. The framework as currently specified cannot detect *factually wrong* answers, only *structurally incoherent* ones. If the v3 demo goes out and the foundation model confidently states a wrong fact, the CAS pipeline cannot intervene — and a user watching the [admissible, register-coherent] trace badge will read the error as endorsed. This is the failure mode that will cause the most reputational damage soonest; mitigation requires either (a) factual retrieval grounding bolted onto the generator path, (b) a hedged-answer mode for low-confidence facts, or (c) deliberately scoping the v3 demo away from factual-recall questions until grounding is wired. Pick one before the demo ships. Open-question 4 in the spec flags this; flagging it again here because it is the load-bearing risk.

### [1] Citation-claim mismatch: RFC 8785 is credited with a normative property it does not contain (schema closure / rejection of unknown keys), contradicting the very next sentence of the same paragraph. | minor | confirmed

- excerpt: These four properties are the normative content of the JSON Canonicalization Scheme (RFC~8785) \cite{jcs}, which the v0.1 serializer follows; nothing in this section is claimed as new. The schema adds only the domain-specific field set of Section~\ref{ch08:sec-schema} and the sorted-digest rule for parent sets.
- problem: Of the four properties enumerated at lines 123-126, the fourth -- "Schema closure. The bytes contain nothing but the declared fields. RFC 8785 (Rundgren/Jordan/Erdtman, June 2020) is a serialization specification only; it contains no provisions for schema validation or rejection of undeclared object members, and its Security Considerations explicitly delegate content validation outward ("Verify the data for correctness according to the conventions defined by the ecosystem"). In a text whose stated discipline is that attributions be licensed, crediting a normative standard with a rule it does not carry is exactly the failure mode the chapter polices elsewhere.
- fix: Split the attribution. Replace with: "Properties 1--3 are the normative content of the JSON Canonicalization Scheme (RFC~8785) \cite{jcs}, which the v0.1 serializer follows; nothing in those three is claimed as new. Property~4 is not supplied by RFC~8785, which is schema-agnostic and delegates content validation to the consuming ecosystem: schema closure is a Project Coherence schema rule, added here together with the domain-specific field set of Section~\ref{ch08:sec-schema} and the sorted-digest rule for parent sets."
